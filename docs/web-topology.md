# 网页的信息层级

网页与 QQ 共用主控、账号、会话和权限，不是另一套 Agent。

页面依次呈现：

1. 运行拓扑：已配置/已关联聊天入口 → 云端主控 → 账号可用执行器。
2. 会话与任务：每条会话自己的设备、工作区、工具权限、待办和结果；同一设备的不同会话分别展示。
3. 执行设备：登记、撤销、显式连接检查、设备默认目录。
4. 聊天入口：完整身份、待确认关联和一次性关联口令。
5. 我的设置与模型/API：账号数据；目前支持服务声明的供应商和个人模型密钥，完整连接/模型目录仍按后续方案实施。
6. 服务管理：仅管理员可见的网关名单、邀请与服务关闭。

`host.json` 可选 `display_name` 为主控命名，例如“东京云端主控”。该名称不参与设备身份判断，未配置时显示“云端主控”。公开拓扑不包含 SSH 目标、令牌、密钥或其他账号设备；普通成员只看到自己的已关联入口，管理员能看到服务配置的入口。

设备 `is_local` 历史字段表示管理员提供的执行器，不保证和主控物理同机。页面使用“管理员提供的执行器”说明来源，不据此推断实际拓扑。

“已登记”只说明账号归属。“检查连接”调用已认证执行器身份探测，显示验证时间与通路；不创建执行会话、不调用模型、不派发命令。该时间不是实时在线承诺。检查仍需浏览器登录、同源和 CSRF，撤销或其他账号设备拒绝检查。

设备默认目录只影响未指定目录的新会话；修改一条会话的工作区使用原有切换流程与忙碌检查。模型、个人数据、工作区、任务和待办分别处理加载失败；局部失败不会把仍有效的账号错误退回登录页。退出登录清理账号内容，迟到的连接检查不能重新显示已清理的数据。

验证：Windows `cargo test -p peri-cloud`、格式和 clippy；DOM 回归使用 Node.js 26：`npm ci --prefix scripts/portal-ui --ignore-scripts`，将 NODE_PATH 设为 scripts/portal-ui/node_modules 后运行 `node scripts/check-portal-ui.cjs`；CI 在 Windows 自动执行。DOM 测试覆盖会话归属、完整转义身份、局部失败、显式探测、迟到请求和成员可见范围。浏览器布局仍应在桌面和手机实看；DOM 测试不能代替视觉验收。Linux 只构建和运行 smoke，不重复 Windows 回归套件。
