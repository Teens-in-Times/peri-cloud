# v0.8.0-rc.1 个人预览候选

此候选整合执行会话、上下文装配和宿主流程保障，供个人预览验证。候选发布不代表生产已升级。此次范围不包含真实模型付费调用、个人 QQ 客户端验收或生产数据库访问、迁移。

## 变化

- 主助手与执行者共用云端 Agent loop，复杂任务异步委派，执行会话可串行复用；持久等待、窗口轮换和原操作查询保留真实身份。
- 主助手按调用固定其他授权设备，不改变默认会话设备；所有写入共用资源协调。
- 工作审批进入现有主会话，以有界事件回合和类型化工具决定，最终仍由 PermissionMiddleware 校验。删除或可能替换先通知；未知投递不放行。
- 宿主编译完整活跃要求、保留原调用身份及回执；摘要请求不提供工具；QQ 展示通过 CommonMark 管道转为纯文本。
- 助手级 SOUL、项目 AGENTS/CLAUDE 回退、分层 Skill 生效目录、按需设备环境与 MCP 发现分开装配。提示词创作入口保留指引与装配参考，不自动部署用户草稿。

## 候选验证

本地已经通过 7 项 cloud_journal 回归，以及旧正式 Windows 宿主 → 当前开发候选的 schema 9 → 24 迁移、重启和旧备份恢复。旧版记忆保留内容及 legacy_import 来源。双平台优化发布包的检查结果由对应 CI 与升级报告给出；本地开发二进制的通过不代替发布二进制验收。

- 现有 cloud_journal 回归更新为 schema 24，并检查旧状态迁移与重复打开。
- 双平台 CI 从固定正式 v0.7.1 包核对 SHA256SUMS 和 BUILD.json，再运行 scripts/smoke-upgrade.py。
- 升级演练从旧正式二进制创建两个全新测试账号、邀请、偏好和一条旧版记忆；使用 SQLite backup API 生成一致备份，复制到新目录迁移至 schema 24，重启新宿主，再将旧备份恢复到另一新目录并由旧二进制登录。
- 演练不接受生产状态路径；模型地址固定为不可用的回环测试端点，不启用 QQ，不会调用付费模型。
- 报告只上传二进制来源、检查结论和非敏感统计，不上传临时数据库、fixture 配置、日志、密码或 Cookie。

这是合成账号、偏好与旧版记忆的升级演练。设备授权、会话历史等表在此 fixture 中为空，不能据此声称现有生产数据已完成迁移演练；执行故障恢复由现有专门联调覆盖。

## 正式上线前仍需完成

1. 在另行授权后，用受保护的生产数据库副本演练实际数据升级；核对账号、设备、OAuth、入口关联、历史及计划，并验证一致备份可恢复。
2. 选用实际模型，完成委派后聊天、补充要求、跨设备小操作、换窗、暂停恢复和有证据验收的一条完整链路。
3. 在真实个人 QQ 客户端检查主动问候、菜单、通知与长文本，观察删除通知是否过密；确认重连和未知结果行为。
4. 为部署环境落实定期备份、恢复验证、磁盘监控和日志轮转。healthz 仅代表进程服务，模型、渠道及执行器需分别检查。
5. 明确迁移窗口、排空任务和放开入口的顺序。接收新业务后不得无条件切回旧库，否则会丢失新业务状态。

## 运行边界

- 单状态目录只允许一个宿主；执行器以启动账号权限运行，不是安全沙箱。
- 资源额度按请求计数，不是精确费用账单；历史和日志仍需部署侧容量监控。
- 任意新调用 ID 的语义重复不自动去重；未知操作仅查询原回执，不能强制算成功或用重发替代恢复。
- 删除分析保守，Write/Edit 和不透明 Shell 可能触发通知。候选保持既定策略，不在发布收尾中扩大自动执行范围。
- MCP 当前不提供项目 .mcp.json 自动准入、stdio 或需要 OAuth/自定义头的连接。

诊断与恢复入口见 [个人预览运维](../preview-operations.md)，完整运行契约见 [执行连续性](../execution-continuity.md)。
