# 执行会话、轮次与上下文窗口

实施状态：schema 19 接入可复用会话、检查点、轮次续接、协作等待及窗口轮换。主助手自动审批、按调用跨设备执行和结构化验收仍属于后续阶段；完整目标尚未交付。阶段记录见 [实施计划](execution-continuity-plan.md)。

## 身份与复用

执行 agent 身份在逻辑执行会话内稳定；任务、运行轮次和物理窗口独立编号。工具调用保留原始窗口、轮次、模型 call_id、参数指纹，以及真实 ToolContext 产生的执行器 invocation_id。调用 ID 与模型 call_id 不可互换。

delegate_task 未指定 execution_session 时新建；提供该字段时显式复用 list_execution_sessions 返回的候选。复用核验可信 OAuth 用户、设备、执行器规范化工作区与文件系统身份、隐私范围、记忆隐私代次，以及所有来源主会话的上下文代次。群聊受众不得相互继承。清空或回退来源主会话会使对应执行上下文失效。

同一逻辑执行会话串行承接任务。暂停或等待的任务仍占据该逻辑会话的顺序位置，但不占用活动推理槽位；独立会话可以在全局及用户额度内继续运行。

## 控制与等待

主助手调用 control_task，提供 task_id、最新 expected_revision 和 action：

| action | 行为 |
| --- | --- |
| pause | 活跃轮次在工具结果落账后的边界暂停；未启动的任务直接暂停 |
| resume | 恢复暂停、等待或明确要求重试的失败任务；先核对旧轮次与操作结果 |
| rotate | 为已经启动的任务请求替换上下文窗口；不撤销原操作 |
| cancel | 取消任务并核对执行器实际状态；取消请求不代表副作用撤销 |

执行 agent 使用 wait_task，提供 reason 与可选 resume_after_seconds（0 至一周），等待外部条件。没有时间参数时由主助手显式恢复。message_parent(wait_for_reply=true) 将问题持久写入账本并排入原主会话，然后停止当前运行轮次；主助手仍可聊天。

主助手用 message_task 回复或补充要求。submitted、consumed、applied 表示不同阶段；worker 消息的 forwarded 仅证明已进入主会话队列，不证明人类读到。重启后未转交的 worker 消息按原事件 ID 继续入队，底层投递未知时仍沿用原发件箱规则。

等待的回复边界来自生成问题前模型已观察的消息序号。不能用问题落账时的全部消息最大序号代替，否则会漏掉模型生成问题期间到达的新要求。

## 检查点与恢复

任务中间件在原 Agent loop 内保存三个边界：

1. model_boundary：即将调用模型时的规范历史及观察水位。
2. dispatching：工具调用意图已持久记录，尚不能据此断言执行成功。
3. tools_settled：整批工具结果已进入规范历史，并保存原始回执。

原生工具包装器在实际派发前保存真实 invocation_id、执行器会话和规范工具名。注册或数据库中存在设备记录不表示设备在线；恢复通过原绑定重新认证执行器，再查询原调用。原始回执与后续对账证据分别保存。

恢复不会调用旧工具完成“重试”。回执不可查、查询失败或执行仍未结算时，保留原任务并等待；404 不代表可以重新提交。只有能够证明未派发，或已经确认原操作结果，才补齐历史并受理新的运行轮次。旧轮次、旧窗口与旧操作记录保留。遗留记录没有足够证据时不会自动重跑。

暂停、等待、换窗不取消仍在运行的后台进程。显式取消和宿主停机走原执行器取消/结算协议。非用户取消导致的中断可以在核对旧状态后续接，不能将服务重启伪装成人类取消。

## 窗口与接班材料

主助手沿用原摘要式压缩；执行 agent 停用摘要压缩，改由宿主管理窗口。RuntimeLimits 新增 worker_window_tokens（默认 48000）和 worker_reserve_tokens（默认 8000）。窗口上限同时受模型会话的上下文容量约束，并估算系统提示词、工具定义和历史体积。估算用于提前换窗，不等于准确 token 计费。

预算压力在启动或工具结果落账边界触发换窗。新窗口携带有界的宿主事实、agent 工作笔记、计划及原窗口/轮次引用；不复制整段 trace 或全部文件读取输出。摘要缺失时也可依靠宿主事实启动。接班材料中的工作笔记和工具结果仍是待核对的证据，不是宿主规则。

旧执行窗口永久保留执行窗口身份，不进入普通聊天历史选择，不投射 worker 工具过程为普通聊天正文。

## 检索接口

inspect_task 提供以下视图，均核验当前账号、任务和隐私边界：

| view | 内容 |
| --- | --- |
| status | 有界任务摘要、当前轮次和等待状态 |
| contract | 完整目标、约束及验收要求；工作笔记标记来源 |
| windows | 逻辑执行会话的窗口分页，返回 window_id |
| conversation | 指定 window_id 的规范可见历史；默认当前窗口 |
| operations | 原窗口/轮次、参数指纹、调用 ID 和执行状态预览 |
| trace | 有界事件预览 |
| messages | 双向任务消息和应用回执 |

使用返回的 next_cursor 翻页。文本预览标记截断；旧窗口读取遵守历史排除标记，并排除隐藏思考。当前必要详情和筛选接口还会随完整目标继续扩展，不将预览冒充完整输出。任务历史与个人长期记忆保持独立，不自动整体写入个人记忆。
