# 多设备管理与选机建议

账号工作台的「执行设备」统一显示登记、租约、认证与能力观测、实际修改占用和工作区书签。它是现有身份、连接和任务账本的投影与目录快捷入口。

## 状态与时间

| 层次 | 依据 | 能证明什么 |
| --- | --- | --- |
| 已登记 / 已撤销 | OAuth 设备归属 | 当前账号拥有设备；登记不证明在线 |
| 已配置 / 上报租约有效 / 已过期 | 宿主管理的连接配置与设备租约 | 存在候选连接及上报、截止时间；不证明此时能认证 |
| 最近通路探测 | 原有身份探测 | 指定观察时间能够验证设备；不代表持续在线 |
| 显式身份与能力检查 | 已认证执行器 `/v1/capabilities` | 此次设备身份、协议、平台匹配，及其声明的工具目录、版本、扩展能力 |
| 工作区实际可用 | 原工作区绑定、规范路径、工具权限和执行回执 | 只有实际绑定及调用才能核验；目录声明和书签不授予权限 |
| 修改占用 / 原操作待确认 / 任务状态 | 原设备 lease、原生操作账本、任务记录 | 显示观测时间、占用会话、未确认操作数和等待状态；不替代原记录的结算 |

显式检查有 6 秒上限，不创建执行会话、工具任务或模型请求。结果只缓存于当前 Gateway 进程，最多 512 台，5 分钟后可清理，60 秒内才参与推荐；重启后需要重新检查。失败取代先前成功观测。旧执行器未声明 `device_capabilities_v1` 时只证明身份与通路，工具目录明确未知，后续仍可按原流程绑定工作区。

任务状态直接读取账本，例如等待执行额度或设备资源、等待主助手答复、等待外部条件、等待原操作结算、需要核对结果、暂停和新窗口就绪。`waiting_capacity` 目前是宿主的合并原因，页面不会猜测哪一个额度不足；同时展示真实修改占用与未确认操作。投影仅聚合本账号，不暴露其他账号的任务、目标或凭据。各表是只读观测，不是跨表原子锁快照；受理仍以原资源协调器为准。

## 接口与书签

- `GET /api/account` 增加 `device_management`，按本人未撤销设备 ID 返回租约、检查、资源占用、书签、最多 16 个已绑定历史目录和新任务建议；不返回端点、令牌、SSH 配置或历史正文。历史目录使用 SQL 标量投影，不反序列化会话历史。
- `POST /api/instances/{id}/inspect` 进行只读认证与目录检查；原 `/connection-check` 保留。
- `POST /api/instances/{id}/bookmarks` 接受 `save {workspace,label}`、`rename {id,revision,label}`、`remove {id,revision}`。均要求浏览器登录、同源、CSRF 和精确账号 / 设备归属；异步检查后再次核验撤销状态。
- 执行器 `GET /v1/capabilities` 复用运输 Bearer 认证，返回 `ExecutorCapabilities {info,tools}`，无需工作区或 session。客户端复核设备 ID、协议、平台和目录长度；无工具执行或权限变更。

Schema 27 新增账号 / 设备 / 规范目录唯一的书签表；26→27 只增加元数据，不改会话、请求、任务或操作身份。每设备最多 32 个书签，名称最多 128 UTF-8 字节、目录最多 4096 字节。保存前由目标设备通过原认证目录接口确认规范路径；重复保存保留原名称与版本。改名和移除要求原 revision，防止多标签覆盖。移除书签不删除文件、会话或任务。

书签在主控重启后保留，但不承诺目录仍存在。打开书签先确认目录，再走原独立网页工作区流程重新认证和绑定；不改变原会话目录或在途操作。模型 `list_devices` 契约不因此扩大，私人目录元数据仍限认证网页使用。

## 推荐与冻结目标

只有近期显式身份与非空工具目录检查成功，且没有设备修改 lease 或未确认原生操作，才显示「新任务候选」。这是供用户选择的建议，不自动切换、迁移、重发或创建任务，也不保证新任务的权限、目录、应用和额度满足。设备恢复后仍从原操作 ID 查询原设备；修改默认设备或打开其他书签不能改变已受理调用的目标。

## 细粒度并发与显式重绑定的后续设计

第一版继续使用整设备修改互斥。按工作区放宽互斥，必须先解决规范文件系统身份、符号链接 / 硬链接别名、跨目录脚本与共享资源；Shell 缺少可证明边界时仍取得整设备锁。锁需要统一的层级顺序、持久 owner、重启后未知占用恢复，以及主助手直接执行与执行任务共用的获得 / 释放协议。仅比较路径字符串无法安全实现。

显式重绑定必须是独立宿主操作：校验真实 principal、OAuth 授权和隐私范围；原会话无运行中模型 / 工具、无已提交或未知结果；目标设备重新认证、规范目录和能力核验；原子固定新绑定版本并使旧检查与审批失效。已完成历史、回执及设备身份保留；原任务不可静默继承新设备。跨设备续作宜新建执行会话，由主助手显式交接目标与证据引用。本轮未放宽互斥或启用迁移。

## 验证边界

模拟模型与本地 HTTP 执行器覆盖检查无执行副作用、账号 / 设备隔离、同源与 CSRF、撤销、书签版本冲突、重启持久化、检查过期和在途修改占用；26→27 验证原会话和受理请求身份保留。门户 DOM 回归覆盖过期观测、等待与占用说明、名称作为文本显示、独立工作区目标和退出后的迟到响应。没有真实模型或生产升级，DOM 回归不替代移动端与桌面视觉验收。
