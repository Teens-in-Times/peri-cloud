## 编辑和保存

节点可拖动、改职责、连线、反转和删除；可以画笔涂画、擦线、添加便签。领域视图控制当前显示，全部模块可查看完整拓扑。鼠标滚轮平移，Ctrl/⌘ + 滚轮缩放；撤销/重做和键盘方向移动均可用。

“分区排版为副本”根据当前画板另存分区版，保留原稿、文字与关系；画线保留原坐标。每个领域有独立位置，拖动只调整当前领域布局。分区选择器可直接放大一个区域，选中模块会突出相关节点与连线。最多保留 32 块画板。

`review-20261019.html` / `.json` 是基于用户本次导出的整理版本，包含全部原画板和新增整理图，使用独立浏览器存档身份。总览的汇总关系只在总览显示；完整关系位于相应领域和“全部模块”。修改说明见 `review-notes-20261019.md`。

修改自动保存在当前浏览器 localStorage，并保留上一份备份。它不会自动同步到其他浏览器或写回仓库。通过“保存 / 导入”下载完整 JSON、带修改的独立网页或设计 Markdown。JSON 保存所有坐标、画线、提示词、意见和参数；独立网页内含当前快照，可直接打开继续修改。来源文档的相对链接仍需原项目目录或项目预览服务。

也可导入旧版 `peri-grok-board` JSON，新增为一块画板。导入整个工作台会恢复其全部设计，可撤销；不会改写导入文件。浏览器存储或下载受限时，窗口中的文本可直接复制备份。

旧版“我们的方案”和“我的草稿”会自动补齐现有基础。升级按旧模板、用户草稿与新模板逐字段合并，保留用户修改的文字、位置、画线、新增对象及删除；已有画线时保持原节点位置。旧存档留作浏览器备份。升级后再次刷新不会补回用户随后删除的模块。领域可选“方案内 · 现有基础”或“方案内 · 新增与扩展”。

## 源文件与构建

- `data.js`：功能拓扑、会话成果、证据来源和行为场景。
- `integration.js`：现有实现与方案的对应、完整拓扑合并和旧草稿升级。
- `layout.js`：功能分区与各领域独立布局；Grok 参考图采用不推断部署位置的分组名称。
- `hierarchy.js` / `prepare-atlas.cjs`：从审阅版本生成职责层级、外部引用、跨图接口和归档。
- `implemented.js`：当前源码的实现快照，扩展现状节点与真实关系；不改写用户设计原稿或 Grok 的证据。
- `navigation.js`：子图目录、面包屑、跳转与引用校验。
- `cache.js`：明确授权的一次性画板缓存重置。
- `prompts/`：主助手、执行 Agent、帧与候选工具契约。
- `canvas.js`：原生 SVG 编辑与自由涂画。
- `app.js`：页面、编辑、校验、保存、导入导出。
- `styles.css` / `page.html`：响应式页面。
- `decisions.md`：保留本轮讨论的原始决定与未决问题。

首次生成重绘数据运行 `node prepare-atlas.cjs`，再运行 `python build.py`。后续只改 UI 时直接构建即可；修改层级规则后重新生成数据。构建默认嵌入 `atlas-workspace.json`，同时更新两个重绘页面。不需要 npm 或构建依赖。浏览器内的编辑需要先导出，不会自行覆盖这些源文件；重新生成不会读取浏览器修改。

验证：`node verify-atlas.cjs` 检查层级、原稿保留、跨图跳转、导入导出和旧缓存保留；`node verify.cjs` 继续验证原编辑器契约。验证使用仓库已有的 jsdom，不安装浏览器或依赖。未执行实屏视觉复核时不能把 DOM 检查描述为浏览器截图检查。

用 `node prepare-review.cjs <用户导出的JSON路径>` 从明确指定的导出生成本次整理版；不修改输入文件。此步骤仅用于已有设计资料，生成的 JSON 使用单行保存。

当前页面是设计工具。原稿的候选接口、N 轮参数与可编辑提示词不代表真实运行配置；已经装配的角色规则和任务工具以现状子图链接的源码及 [核心实现说明](../../core-agent-refactor.md) 为准。Grok 的证据边界参见工作台“来源与边界”和已有研究文档。
