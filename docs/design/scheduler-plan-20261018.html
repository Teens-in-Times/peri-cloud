01 / DECISIONS

先确定边界，再实现可靠性

结构决策 · 推荐

独立 crate，依赖单向

peri-cloud → peri-scheduler。调度库不依赖云宿主、Agent、QQ、设备工具或记忆后端。

部署决策 · 推荐

核心共用，宿主可选

同一个库提供内嵌运行与可单独构建的命令行宿主。独立常驻模式需经过协议和所有权验收后开启。

上下文决策 · 推荐

先接现有会话

触发时走原 Runtime 的上下文入口。当前个人偏好和文本记忆照常生效，未来记忆后端在此入口演进。

第一交付覆盖

一次性、固定间隔、五段 cron 与显式时区；持久记录；暂停／恢复／删除；去重、过期、重启恢复；Agent 工具管理；个人号主动消息；记录分离的执行与送达结果。

保持原有权威

CloudRuntime 持有 Agent 执行；PermissionMiddleware 决定工具审批；MessageAdapter 负责平台投递；账号服务解析真实归属。调度库仅派发任务引用。

主动聊天绑定聊天目标；设备任务绑定执行目标。切换电脑不应使下午问候失效。已开始的设备执行仍冻结原身份与目录。

范围边界：完整调度器与后续扩展

第一交付将调度生命周期做完整。跨会话语义记忆、Skill 自动晋升、多节点 HA、任意插件安装、通用 Shell 作业、广泛第三方平台接入不纳入本次实现。Webhook 触发和自主调整计划保留扩展点，按实际需求另行验收。

“自主关怀”是主动交流策略加周期唤醒，复用同一个调度核心；它不会发展成第二套 Agent 或另一个计时后台。

独立进程如何避免双写与双重执行

内嵌模式使用云宿主提供的连接和所有权。独立模式由调度宿主独占专用状态目录；云端的计划管理通过已认证控制接口访问调度宿主，不再直接修改同一份计划。两种运行方式互斥，不能同时驱动同一状态。

独立模式只传任务引用和触发身份。云端仍验证账号、任务版本、聊天归属和设备约束。受理令牌与 endpoint 属于宿主配置，不成为模型参数。迁移必须先排空派发或保留待核实记录，再转移唯一所有权。

库的 schema 版本使用专用元数据表，避免覆盖宿主 SQLite 的 PRAGMA user_version。独立数据库和内嵌表共用同一套调度迁移逻辑。

03 / DESIGN IT TWICE

先看三种接口形态

比较重点是调用方能否正确使用、边界能否容纳真实故障，以及接口背后隐藏了多少复杂度。以下均为契约草案。



综合建议
公共面采用托管式门面，内部使用原子领取与持久派发记录。把时钟、存储、派发作为少数可替换端口；未来独立宿主复用门面，远程协议不侵入时间算法。


拟议公共面：三个入口，隐藏领取与恢复
Review sketch · not a compiled API
impl Scheduler {
  async fn apply(&self, scope: OwnerScope,
                 command: ScheduleCommand) -> Result<CommandReceipt>;
  async fn inspect(&self, scope: OwnerScope,
                   query: ScheduleQuery) -> Result<QueryPage>;
  async fn run(&self, stop: CancellationToken) -> Result<DrainReport>;
}

trait TaskDispatcher {
  async fn submit(&self, request: DispatchRequest) -> SubmitOutcome;
  async fn lookup(&self, id: OccurrenceId) -> LookupOutcome;
}

enum SubmitOutcome {
  Accepted { run_ref: RunRef },
  Deferred { until: InstantUtc, reason: DeferReason },
  Rejected { reason: RejectReason },
  Unknown,
}
enum LookupOutcome {
  Accepted { run_ref: RunRef },
  DefinitelyNotAccepted, // 权威确认；普通 404 不足以证明
  Unresolved,
}
OwnerScope 是由可信应用层构造的资源范围；模型不能直接提交 owner。远程宿主需要重新认证并解析范围。调度库在范围内过滤资源，应用层负责账号权限。
计划命令携带 command_id；更新还要求 expected_revision。同一命令 ID、不同请求摘要必须返回冲突。Store 不暴露“先读后写”的松散方法组合，使用原子业务操作：应用计划命令、领取到期项并生成触发、记派发状态、结算回执。调度器不会持有数据库事务等待网络或模型。



04 / DURABILITY
计划、触发、执行、送达分别记录
Schedule何时触发哪个 TaskRef
带版本、时区与过期策略
Occurrence这一次触发的唯一身份
保存原计划时间与快照
Run云端受理后的执行回执
由原 Runtime 持有
Delivery最终消息的实际投递结果
由原发件箱持有


稳定身份
周期触发去重键为 (schedule_id, planned_at_utc)。计划版本作为不可变快照保存，不通过版本变化制造第二次同刻触发。
手动“立即运行”使用独立 request_id，不消耗未来的定时槽位。TaskRef 与其版本共同冻结进触发记录。
明确保证
库保证本地触发去重与派发记录可恢复；跨 Agent、执行器和消息平台的副作用遵循原系统契约，不宣称端到端 exactly-once。
已经开始、受理未知、发送未知是不同状态，分别通过原回执查询。未知结果不得自动换 ID 重新执行或重新发送。


1
一次事务领取到期计划事务边界
建立唯一 Occurrence、保存计划／策略快照、推进 next_at，并记录待派发。提交后才离开存储层。
2
开始派发前再检查状态
确认所有权、计划启用状态与启动期限；记录 dispatching，再调用 Dispatcher。关闭服务时停止领取新工作，保留已持有 future。
3
云端受理冻结本次执行身份原准入事务
先查询持久 (owner, occurrence_id) → 原 session／turn／run 映射；已有回执直接返回，不能先解析当前聊天再去重。新触发才解析目标与上下文，将映射、额度和准入原子提交；绑定不可变 TaskRef 版本与请求摘要。设备任务同时冻结 device／workspace／权限版本。
4
Agent 完成后建立投递
只将对外回复交给现有发件箱。发送前再核对归属、联系设置、context_generation 和消息有效期；会话已清空则抑制旧回复，不为同一次触发重新生成。记录实际平台发送回执，不推断收件人已读。


时间规则与错过触发的处理
规则拟议契约
一次性／相对延迟绝对时间要求 RFC3339 含 offset。相对延迟在创建时换算为持久 UTC 时刻，重启不重新开始倒计时。
固定间隔保存 UTC anchor，以 anchor + n × interval 推算，避免按任务结束时间累计漂移。
cron五段表达式与显式 IANA 时区。服务器时区不隐式改变任务；夏令时跳时／重复小时策略在实现前以测试锁定。
过期与积压支持 Skip、Latest，以及受硬上限约束的有界补做。问候默认过期跳过；汇总可合并最近一次；未知执行不进入补做。
忙碌与重叠CloudDispatcher 根据原 Runtime 的运行状态判断同聊天／同任务重叠，返回 Deferred 或 Rejected；执行未知仍占用原槽位。调度核心只控制派发并发与启动期限，不能用受理回执推断运行已结束。尚未受理项可在 start_deadline 内延期，复用原 Occurrence；到期记 skipped。
暂停／删除／取消暂停和删除停止后续触发与未开始派发项；dispatching／已受理项不能伪报停止。取消执行另走 Runtime，回执单独展示。


重启恢复与所有权
pending 且可证实尚未开始派发：在所有权恢复后继续；dispatching：先查同一个 Occurrence 的原受理回执；Unknown：保持待核实。仅权威确认 DefinitelyNotAccepted，且仍在有效期内，才允许再次提交同一身份。
第一交付为单所有者运行，沿用独占状态目录和排空生命周期；不会将租约到期直接等同于外部执行已经结束。多节点选主与远端 fencing 属于独立模式验收内容。
数据清理保留有界去重凭据与未知结果。不能因删除历史而使旧触发再次有效；不能把被暂停／删除的计划在恢复时复活。



05 / CONTEXT
记忆从原会话进入，调度核心保持稳定
主动聊天
Task 保存已授权的意图和聊天引用。触发时由云端解析该聊天当前可见上下文、个人偏好与已有文本记忆。
纯聊天不装载设备文件／Shell 工具，不要求执行器在线。用户回复通过同一个会话服务接续。
设备任务
Task 保存受授权的设备与工作区选择。云端在每次受理时验证设备身份、目录和现有未决结果。
运输凭据由宿主持有；审批仍经过 PermissionMiddleware。切换设备不会改写已经开始的 Run。


未来记忆系统接入统一上下文入口。调度器不读取 MEMORY 文件、不检索向量库，也不保存一份会过期的个人记忆副本。


现有会话绑定设备：本次必须处理的接缝
当前 FrozenSession 带 device 与 workspace，已有工作稿虽然允许 remote=None，仍保留设备坐标。正式设计需要一个云端的纯对话准入分支：它能在相同聊天归属下工作，不能用虚拟 device UUID 伪造执行器身份。
范围控制：优先在云端应用层添加聊天引用解析和纯对话运行上下文，不在调度 crate 中重做会话系统。若现有模型无法表达“无设备的对话”，须先补足公共契约，并验证既有设备会话兼容性。
切换电脑时，聊天目标保持原 route；首次受理的新 Run 才解析 session 与 context_generation，并持久化该结果。受理回执丢失后，即使 /new 或切换设备，也先返回原映射。聊天解绑、账号撤销或 route 被替换时，不自动迁移给另一个身份。


后台检测、生成消息与会话连续性
后台检查过程和失败诊断留在运行记录。真正对外发出的助手消息，通过统一会话服务关联到目标聊天；保留来源是 scheduled event 的事实，不伪造成用户刚发了一条消息。
发件箱与对话投影共享 message_id／delivery_id 关联。回复到来时能解析原发言。发送结果未知时保留“已生成／发送待核实”的状态。内部 delivered 仅表示平台确认接受发送；message_id 不证明收件人已收到或读过。生成后若 /clear 改变 context_generation，未发送的旧消息须抑制；同一触发不切换上下文重新生成。
后台写回和用户入站消息必须经过同一会话串行入口。上下文压缩仍由原 Runtime 管理，不另外导出一份隐形会话历史。


工具与主动联系策略
固定工具作用
schedule_create在已授权范围内创建计划，返回解析后的时间、目标和稳定 ID。
schedule_list分页列计划与最近触发，创建前可查询以避免重复安排。
schedule_update以 expected_revision 修改时间、意图、暂停与恢复。
schedule_remove停止后续计划；与取消已开始执行明确分开。
模型参数只表达意图、时间与允许的目标选择。owner、权限和实际聊天坐标由服务端解析。Web 写操作继续要求 Cookie、同源与 CSRF；QQ 继续检查精确聊天归属。
主动联系开关、时间窗口、每日频率和冷却由云端策略先判断；实际发送前再检查。Agent 再决定 Send／Silent，调度核心不解析回复中的魔法字符串。普通后台轮次默认不能创建新计划；允许自调整的任务需要显式能力与预算。
个人 QQ 通过 OneBot 主动发送；官方 QQBot 的主动推送受平台限制，采用可查询的工作台结果。平台能力由 Adapter 声明，不以“已配置”冒充“已送达”。

07 / DELIVERY PLAN
按可验收的边界推进
每阶段都有独立退出条件。计划不以文件拆分完成度替代行为验收，也不估算未经测量的工期。


S0 / CONTRACT
冻结术语与行为契约
确定四类记录、工具范围、聊天引用、执行模式、暂停／删除语义、时间过期策略与唯一所有权。盘点现有工作稿，将可复用部分映射到新边界。
退出条件：接口方案与关键默认值经评审；未决项有明确推荐，已有工作稿不被回退或丢弃。


S1 / CORE
建立独立 crate 与可测试时间模型
实现领域类型、Clock、时间规则、存储契约和命令版本控制。独立二进制先提供 check／preview。迁移按宿主与库分别持有版本。
退出条件：能单独构建 crate／二进制；依赖树不引入 Agent、TUI、QQ；虚拟时钟和时间边界测试通过。


S2 / DURABILITY
实现持久领取、派发与恢复
完成原子计划推进、Occurrence 去重、派发状态机、权威回执查询、过期／合并策略、公平准入和排空生命周期。
退出条件：故障注入证明未知副作用不重放；数据库清理和重启不会复活已结束触发。


S3 / CLOUD
对接原 Runtime 与纯聊天上下文
建立 ScheduledTaskService、CloudDispatcher、固定工具、认证控制接口与后台预算。补足设备无关的聊天准入，读取现有偏好／文本记忆。
退出条件：新建聊天或已选设备聊天均有明确合法路径；PC 离线仍能问候；用户回复可接续；设备任务仍走原审批。


S4 / DELIVERY
打通个人号主动消息与可核实回执
使用原 MessageAdapter 和发件箱；对接联系策略、发送前复核、会话投影和独立送达状态。QQ 文本入口和网页调用同一业务服务。
退出条件：协议回归通过；在独立测试个人号上验证主动问候与连续回复；真实客户端未验收时明确列出。


S5 / MIGRATION
迁移工作稿，完成发布回归
识别生产 schema 与合法工作稿数据，保持原计划／触发／请求键映射。旧计划保留 LegacyFrozenSession 的 session／device／workspace 语义，不能静默扩展成跟随聊天路由；需要转换的计划先暂停并明确选择。停止新增派发、排空或保留未知项，再切到新实现。旧 Gateway 调度代码在新链路验收后收拢。
退出条件：原工具／审批／QQ／Web 回归通过；许可与上游归属完整；有一致备份、前向修复和兼容回退说明。


S6 / STANDALONE
