# Peri 记忆与自创 Skill 方案

实施进展（2026-10-18）：USER/FLEET/DEVICE_ENV 条目、上下文帧与遗忘上下文隔离已实现，运行契约见 [memory.md](memory.md)。以下保留研究与分期设计；项目授权与 CONTEXT、后台提炼、候选箱与自创 Skill 尚未交付。

状态：研究与设计，尚未实现。调研日期：2026-10-17。现状基线：v0.5.0。

后续用户草案、模型/API 目录、自动切设备和三级 Skill 披露的细化见 [跨设备上下文与模型接入设计](context-and-model-control-design-20261017.md)；涉及提示词快照时机与披露规则，以该文为准。

建议先交付“可查、可改、可忘的记忆”，再交付“从成功任务生成、经确认启用的技能”。继续使用现有 Agent loop、账号身份、PermissionMiddleware 和远程执行器。QQ 是完整日常入口；网页用于并列展示和批量编辑，不成为必经步骤。

## 1. 用户只需要理解四件事

| 名称 | 回答的问题 | 例子 | 用户入口 |
| --- | --- | --- | --- |
| 偏好 | 希望 Peri 怎样配合我 | 回答先给结果；操作前说明目标设备 | `/偏好` |
| 记忆 | 希望以后还能想起哪些事实 | 这个项目的正式环境在东京 | `/记忆`、自然语言“记住” |
| 历史 | 以前具体发生过什么 | 上周那次部署的命令、结果和对话 | 会话列表、历史搜索 |
| 技能 | 希望复用哪套做事方法 | 发布前检查、备份、部署和验证的流程 | `/技能`、自然语言“把刚才的流程存成技能” |

设备实时资源、在线状态和网络流量必须重新查询，不能把历史观测当成当前状态。记忆可以保存“服务器 A 是测试机”，不能把“一次内存占用 80%”长期当成现状。记忆和技能都不授予访问入口、设备或执行工具的权限。

用户不需要维护 MEMORY.md、USER.md、SOUL.md 等文件。导入、导出可以兼容文件格式，产品界面使用上表中的概念。

## 2. 当前代码已经具备什么

- `peri-cloud/src/personal.rs` 已有账号绑定的 `ReadMemory`、`WriteMemory`；模型不能传入其他账号身份。写入沿用权限审批，带版本号核对。
- `peri-cloud/src/core.rs` 在个人任务开始时读取偏好和记忆，加入本轮上下文；它们作为个人资料使用，不替代系统规则或工具权限。
- `peri-cloud/src/state/userdata.rs` 保存偏好与整段记忆，两者共享 revision；默认合计有大小限制。目前没有条目来源、检索索引、过期、冲突或删除生命周期。
- QQ 已有个人设置菜单，适合继续扩展，没必要另造一套设置产品。
- `peri-middlewares/src/skills/` 已有 SKILL.md 发现、摘要、按需加载和来源信息，MCP 也有 Skill 发现路径。
- `peri-cloud/src/assembly.rs` 刻意没有启用本地 Skill、hook、Git 等需要本地 cwd 的能力。直接打开这个开关会让东京主控的文件系统冒充用户选择的执行设备，不能这样接入。

因此当前问题是“云端的存储、范围与生命周期还没接好”，不是缺一个新 Agent 框架。

| [Letta](https://docs.letta.com/v1-sdk/memory/memory-blocks) | 用有名称和大小边界的资料块组织常驻上下文，可设只读；整块更新有并发覆盖风险 | 常驻资料有固定预算，区分用户明确资料与观察 | 保留 Peri 已有 CAS，条目更新逐项核对版本 |

| [Agent Skills 标准](https://agentskills.io/specification) | SKILL.md 元数据、正文和资源渐进加载 | 兼容 SKILL.md、scripts、references、assets | 账号、版本、能力需求和启用状态由服务端管理，格式不承担授权 |

Hermes 当前文档还允许更新可写的外部 Skill 目录，不能沿用旧版本“外部 Skill 一律只读”的印象。其固定源码中的 Skill 写入审批导入失败分支会放行写入；Peri 若配置必须审核，则审核设施不可用应返回失败，不能默默生效。这是本次选定版本的具体实现观察，不是对整个项目的安全评价。[Hermes Skill 文档](https://github.com/NousResearch/hermes-agent/blob/e4635a16a6367f63003feb9c0447c5e6375fbd04/website/docs/user-guide/features/skills.md)、[写入门控实现](https://github.com/NousResearch/hermes-agent/blob/e4635a16a6367f63003feb9c0447c5e6375fbd04/tools/skill_manager_tool.py)。

参考用于判断产品和工程取舍，不复制对方的 Agent loop 或后台自学习系统。

## 4. 记忆：条目是权威，摘要和索引可重建

### 4.1 范围与隐私

第一阶段只做“我的记忆”和现有账号可访问项目的记忆。项目没有独立身份与成员授权时，先只交付个人范围，不用目录字符串假装项目权限。

每条数据的 owner、scope 和可见范围由已认证会话捕获。模型只提供内容与目标范围建议，不能指定任意 principal。检索、读取原文、编辑、导出、后台整理分别检查权限；不能只在搜索入口过滤一次。

群聊默认不注入账号的私人资料。一个群进入网关白名单，只代表它能进入产品，不代表成员同意把全部聊天收进记忆，也不代表私人记忆可以在群里公开。群内希望保存的内容必须有明确范围和确认，且只来自已受理的对话。

### 4.2 建议的数据契约

`MemoryItem` 至少包含：

| 字段 | 目的 |
| --- | --- |
| id、owner、scope | 稳定引用与服务端范围校验 |
| content、kind | 原子事实、决策、偏好引用等；避免一个大段落覆盖全部资料 |
| source_turn、source_message、source_kind | 能回答“为什么记住这个”，区分用户确认、工具观察和旧文本导入 |
| status、revision | 待确认、有效、被替代、已删除；并发修改使用 CAS |
| observed_at、valid_until | 时间与时效；动态观测使用短有效期，必要时重新查询 |
| supersedes、content_hash | 保留更正关系，防止重复添加与矛盾条目同时生效 |

没有原始消息证据的旧记忆，按一条“旧版导入”记录迁移，保留原文。不要自动拆成一串看起来有精确来源、实际上没有证据的事实。

另有候选队列、删除抑制记录和后台任务记录。摘要与 FTS 索引是派生物，可以重建；事实条目及其版本是权威。

### 4.3 上下文与检索

每轮开始固定一次可见的记忆版本：少量明确偏好和置顶事实常驻，其余由 `SearchMemory`、`GetMemory` 按需加载。返回内容附来源、时间、范围和状态，限制结果条数与字节预算。原始历史搜索是另一条能力，仍需校验历史可见性。

本轮工具可读取刚写入的版本；已确认修改从下一轮稳定注入，避免改写正在执行和审批中的上下文，也避免 QQ 长会话一直使用旧资料。

先使用 SQLite FTS5、实体精确匹配和时间/范围过滤。中文要专门验证分词：不能假定默认 unicode61 对中文查询足够。可试 trigram 或应用层分词；短于三个字符的词、设备别名、QQ 号、路径和代码符号另做精确匹配。向量检索作为后续可选增强；未配置 embedding 时仍能正常使用，不强迫用户多部署一个数据库。

### 4.4 保存、更正和忘记

- 用户明确说“记住”：展示将保存的内容和范围，沿用现有确认与写权限；确认后反馈“已记住，可在 `/记忆` 修改”。
- Agent 推断：进入候选队列，默认不改变用户资料；完成任务后合并成一次“有两条建议记住的内容”，用户逐条或批量确认。
- 自动整理可选择开启，菜单明确说明保存范围、来源和保留期限。默认不自动推断敏感个人资料，不收录密钥、凭据或原始工具大输出。
- 用户更正：新版本替代旧事实，后续回答只用有效版本；必要时说明证据冲突，不能挑一个版本默默猜。
- 用户忘记：立即使条目不可召回，并删除派生索引；以条目标识、来源和删除代次阻止旧候选或重建任务把它再次写回。

“忘记记忆”和“删除聊天记录”是两个明确操作。界面说明历史是否仍保留，不能承诺删除所有数据后还悄悄留下原文。备份的保留和恢复也要尊重删除状态；只保留必要的无正文审计与抑制信息。

### 4.5 QQ 操作示例

```text
我的记忆 · 第 1 / 1 页 · 2 条
本页 1—2 项，完整显示内容与范围

1. 正式环境部署在东京
   范围：我的账号；来源：你在一次部署任务中的确认
   操作：查看来源 / 更正 / 忘记
2. 项目默认使用 Windows 执行器
   范围：我的账号；来源：你明确要求记住
   操作：查看来源 / 更正 / 忘记

搜索记忆 / 添加记忆 / 待确认内容 / 返回
```

以上是交互草图，不表示当前已经保存这些示例事实。官方 QQ 使用原生按钮；个人 QQ 使用完整编号和引用菜单，复用 v0.5.0 的动作所有权、过期、草稿和版本核对。删除、清空、导出与切换自动整理均有具体确认。群内仅显示当前群可见内容，不把私人列表发到群里。

## 5. 自创 Skill：版本化的流程，而不是偷偷修改自己

### 5.1 生命周期

```mermaid
flowchart LR
    A[已完成且有结果证据的任务] --> B[生成技能草稿]
    B --> C[格式与资源校验]
    C --> D[QQ 查看完整内容和变更]
    D --> E[用户确认启用某个版本]
    E --> F[下次任务按需发现和加载]
    F --> G[在选定执行器执行并记录结果]
    G --> H[提出改进草稿]
    H --> C
```

默认触发语是“把刚才这套流程存成技能”。失败任务可以提炼排错方法，但必须把未解决步骤和证据缺口写明，不能把失败流程发布成已验证方案。后台只提候选，不自动启用，也不为每次简单问答制造技能。

Skill 保留标准目录：`SKILL.md`、`scripts/`、`references/`、`assets/`。服务端另外保存 skill_id、owner、scope、revision、内容哈希、来源任务、校验报告、启用记录和能力要求。已启用版本不可原地修改；改进产生新草稿，支持比较、回退、停用、导出和删除。

外部技能可导入后保留来源和许可证信息。用户的修改生成自己管理的版本，不直接改外部或项目原件。同名技能以来源和稳定 ID 区分，避免导入后悄悄覆盖已有流程。

### 5.2 与云端、设备的接线

新增账号范围的 Skill 服务，接入现有 Skill 摘要、按需内容读取与 MCP 发现契约。先验证现有 seam 能承载远端内容和资源，再提取最小 provider；不另造推理循环，不直接扫描东京主控的 `~/.peri/skills` 作为所有人的技能。

本轮只固定技能目录摘要和版本引用，使用时加载正文，资源再按需读取。目录变化在下一轮生效；已审批的内容和脚本哈希不会因后台更新改变。

脚本在当前已授权执行器运行。能力检查针对目标设备的 OS、解释器和工具；东京有 Python 不等于服务器 B 有 Python。资源下发需要受控、限量、校验哈希的执行器路径，继续走已有文件写入/执行权限，不通过模型参数携带 SSH 私钥、端点令牌或连接配置。符号链接、父目录逃逸、超大资源和重复文件名必须在接收边界拒绝。

启用技能只表示允许 Agent 使用这套指导；其中的 Bash、写文件和外部动作仍按现有规则审批。审批绑定本次技能版本、脚本哈希和设备；换版本或换设备时重新检查，不能把以前的批准套到不同动作上。

### 5.3 最小工具与菜单

优先复用现有 Skill / DiscoverSkills 的工具语义，新增的能力只承担草稿和生命周期：发现可用技能、读取指定版本、提出草稿。启用与批准由用户交互后的服务端动作完成，模型不能“批准自己的草稿”。

```text
技能：服务发布检查
版本：3；状态：草稿；适用：Linux，有 systemd 的设备
来源：一次已完成的发布任务
本次更改：增加备份校验和失败回滚说明

查看完整步骤 / 查看脚本 / 查看版本差异
试用本次任务 / 确认启用 / 修改草稿 / 丢弃草稿
```

“试用”也要先满足目标设备与工具权限；没有安全试用条件时，界面如实标记“未执行验证”。列表和差异使用现有分页，不以省略关键命令的卡片代替确认。

## 6. 后台整理的边界

后台任务有持久 ID、来源 turn、输入版本、预算、状态和取消信号，进程退出后可以恢复已知状态。只整理已经结束的任务；未结束的执行、待确认的投递和未决审批不能被当成成功经验。

按账号合并短时间内的候选，避免每轮启动多个整理 Agent。用户开始新任务时可延后低优先级整理。按来源与内容版本去重；删除或更正后的旧任务不能覆盖新资料。未知结果不自动重复写入。

所有写入通过同一 Memory/Skill 服务处理 CAS、范围、审计和确认。QQ、网页、后台和模型工具不能各自写一份文件，最后再靠双向同步解决冲突。

## 7. 分阶段交付与验收

| 阶段 | 可交付行为 | 必须通过的验收 |
| --- | --- | --- |
| A：可控记忆 | 旧资料迁移、条目与来源、QQ 增删改查、默认范围、基础检索 | 重启仍可用；更正下一轮生效；中文与设备 ID 可查；并发不丢更新；群聊不泄露私人资料；忘记后索引重建不复活 |
| B：可用技能 | 手动生成草稿、QQ 完整查看、确认启用、选定设备执行、回滚 | 同名来源不覆盖；未批准草稿不生效；Windows/Linux 能力正确；脚本改动不沿用旧审批；退出和重连不重复执行 |
| C：辅助整理 | 可选后台候选、历史检索、技能改进建议 | 有证据才提炼；无内容可保存时不凑数；删除与新版本能挡住旧后台任务；成本有上限 |
| D：检索增强 | 依据中文召回评估选择混合检索、排序与压缩 | 对固定样本比较召回率、错误事实率、延迟和成本；无 embedding 时降级仍可用 |

评估使用脱敏的真实任务类型，并保留未用于生成的变体：更换设备、目录、端口和故障条件。测量是否少走步骤、减少重复问法，检查是否误用旧事实或把示例常量当成现场参数。跨账号泄露和错误目标执行必须为零；回忆失败应明确说没找到，不能补造“你以前说过”。性能先记录基线，再约定预算，不虚构提升比例。

建议先做 A，再做 B。向量库、全自动资料改写、多层用户人格和自我修改 Agent prompt 不放进第一版；它们不能替代范围、来源、删除和审批这些基础能力。
