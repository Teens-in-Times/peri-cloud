# 调度器与主动聊天

`peri-scheduler` 是独立 Rust crate，负责时间、持久触发、派发记录和恢复。`peri-cloud` 提供账号、任务引用、会话上下文、原 Agent Runtime、工具审批和 MessageAdapter；调度库不反向依赖这些组件，也不保存记忆副本。

## 使用

个人 QQ 可以直接交代“每天下午两点问候我”，Agent 使用 `schedule_create` 工具创建计划，并沿用原审批。固定工具还包括 `schedule_list`、`schedule_update`、`schedule_remove`、`schedule_runs`。自动触发的轮次只保留只读计划工具，不自行创建新的周期任务。

不经过模型的文字入口：

```text
/定时
/定时 一次 2026-10-19T14:00:00+08:00 和我说下午好
/定时 周期 Asia/Shanghai 0 14 * * * | 轻松问候一下我
/定时 暂停 UUID 版本号
/定时 恢复 UUID 版本号
/定时 删除 UUID 版本号
/定时 记录 UUID
```

网页“会话与任务 → 主动聊天与定时任务”提供创建、编辑、暂停、恢复、删除及触发记录。主动联系设置可关闭所有聊天问候、设置自动关怀窗口和每日后台任务额度。没有已注册设备时，已关联聊天可以创建明确的云端对话；选择设备后仍走原设备验证与工具审批。

新聊天计划跟随原授权聊天的当前会话，切换电脑不使计划失效；设备计划冻结创建时的会话、设备和工作区。历史工作稿计划标记为 `legacy_frozen_session`，保留原语义；要改成跟随聊天，请删除旧计划并创建新的聊天计划。暂停和删除停止后续及尚未开始派发的触发，已开始的执行需通过原取消入口处理。

## 时间与联系规则

- `once`：RFC3339 含 offset，一次性时间。
- `after`：正整数秒，创建时换算 UTC，重启不重新倒计时。
- `interval`：UTC 秒数 anchor 加固定秒数间隔，不以执行结束时间计算下一次。
- `cron`：严格五段表达式加显式 IANA 时区。不存在的夏令时墙钟时刻跳过，重复时刻仅使用较早的那次；所有 UTC 游标严格前进。

云端当前默认启动有效期为五分钟；问候过期跳过。忙碌时保留同一个 Occurrence，在有效窗口内延期；未知执行和受理结果不通过换 ID 绕过。库另有 `Latest`、有界 `CatchUp` 策略供可信宿主使用，云端默认不补发过期问候。

`always` 表示用户明确约定时间的消息；`when_useful` 在联系窗口内由 Agent 判断，无必要时返回内部静默结果。默认自动关怀窗口为 Asia/Shanghai 08:00–22:00，每日后台任务上限 20；账号可以修改。明确约定时间不受关怀窗口限制，主动联系总开关仍在生成前与发送前检查。后台额度也适用于设备计划，原云端额度和并发限制继续生效。没有隐式创建的问候计划，必须先由用户安排或授权创建。

## 记录、恢复和隔离

周期触发身份由 `(schedule_id, planned_at_utc)` 决定，不因编辑计划而产生第二次同刻触发。Occurrence 固定不可变 TaskRef 版本，编辑不改写已领取的任务内容。

云端以 `(owner, occurrence_id)` 全局查询原 session/turn；受理映射、轮次与额度在同一事务中提交。超时或丢失回执先查询原任务，即使此时 `/new` 或切换了设备也不会重复扣额或创建第二次执行。不同内容复用同一个命令或触发身份会冲突。

生成成功与发送结果分别展示。`delivered` 表示平台确认接受发送，不证明收件人已收到或已读。发送未知不自动重发；用户可查看记录与原任务结果。发送前再次核对聊天归属、联系设置、有效期、当前会话与上下文代次，`/clear` 或回退后尚未发送的旧代次回复被抑制，同一触发不会换上下文重新生成。

重启不重放运行中或未知的工具副作用。调度派发未知通过原回执核实，只有本地权威确认从未受理，才会在有效期内重新提交同一触发。迁移前没有全局受理证据的旧未知记录继续保持未知，不推断为失败后重做。

计划每账号最多 20 个，全局最多 1000 个；计划列表返回账号现有计划，触发查询返回最近 100 项。存储保留历史与去重证据，目前没有自动历史压缩策略，运维需按实际规模管理状态目录。

## 构建与独立二进制

```sh
./scripts/cargo-rmcp-patched.sh test --locked -p peri-scheduler
./scripts/cargo-rmcp-patched.sh build --locked -p peri-scheduler --bin peri-scheduler
./target/debug/peri-scheduler preview --timing '{"kind":"cron","expression":"0 14 * * *","timezone":"Asia/Shanghai"}' --after '2026-10-18T00:00:00Z' --count 3
./target/debug/peri-scheduler check --timing '{"kind":"interval","anchor":1792281600,"every_seconds":3600}'
```

Windows 可运行同目录的 `peri-scheduler.exe`。二进制仅提供 `check` 与 `preview`，不需要模型、聊天账号或运输凭据，不访问生产数据库。现有 host/executor 发布包保持原构成，规则检查器可按上面的命令单独构建。

调度执行默认内嵌在唯一云宿主中，复用其 SQLite 连接与目录锁。不要启动第二个写同一云状态目录的进程。远程常驻 `serve` 模式需另行完成认证控制协议、原受理回执查询及所有权转移的验收，目前不提供此模式。

## 数据库升级

云宿主 schema 9 可直接升级到 11。schema 10 工作稿迁移保留计划 ID、触发时间、原请求键、冻结目标和未知记录；旧未发消息缺少可靠的上下文代次证据，会被抑制，不补发。原表保留供审计，新的云适配表与调度库表承担后续运行。

调度库自有 `scheduler_metadata`，不覆盖宿主的 `PRAGMA user_version`。升级前保存一致的 SQLite 备份；旧程序拒绝新 schema，回退必须恢复匹配旧程序版本的完整状态快照。不要仅降低 `user_version`。当前没有多节点同时写入或自动主控迁移能力。
