# 网关访问控制

访问控制决定哪些聊天来源可以进入 Peri。它属于 Gateway 的公共基础设施，官方 QQBot、OneBot 和后续适配器使用同一套规则、菜单、存储与审计；适配器只负责可信发送者、私聊 / 群聊分类和平台标识校验。

## 管理入口

已关联的管理员在机器人**私聊**发送 `/网关` 或 `/访问控制`，也可从主菜单选择“网关与访问控制”：

1. 选择要管理的入口，例如官方机器人或个人 QQ。
2. 选择“允许的用户 / 允许的群 / 屏蔽的用户 / 屏蔽的群”。
3. 点击“添加一项”，然后发送完整标识；个人 QQ 使用 QQ 号或群号。输入四分钟有效，可发送 `/取消设置` 退出。这次输入不交给 Agent。
4. 每页完整显示六项，可前后翻页，点击“移除”删除一项。模式切换需要再次确认。

新增入口的引导白名单由部署者首次配置，后续菜单修改持久保存，重启时不会被配置覆盖。官方 QQBot 显式保留升级前的来源行为，之后管理员可在同一菜单修改。

| 模式 | 私聊 | 群聊 |
| --- | --- | --- |
| 白名单（新入口默认） | 允许的用户 | 用户和群都必须允许 |
| 黑名单 | 未屏蔽的用户 | 用户和群都没有被屏蔽 |

任何模式下黑名单优先。名单按**入口实例**隔离，官方 OpenID 与个人 QQ 号不能互换；名单中的允许不代表已关联账号，不授予设备、会话或工具执行权限。没有匹配的来源被静默拒绝，不产生绑定提示、不调用模型，也不查询引用消息。

普通成员不能管理入口的全局规则；群管理员头衔也不等于 Peri 管理员。群中不展示名单。菜单动作继续绑定真实发送者、聊天、过期时间和单次消费；规则修改另外核对策略版本。旧页面与旧按钮不能覆盖新的规则。更改有操作者、时间、版本和策略快照审计记录。

新增规则影响之后的入站、按钮回调及发件检查。名单收紧后，尚未发送的结果与卡片会被抑制，不能因重连重新投递；已经发出的平台消息无法撤回。策略变更不自动取消已在执行器运行的任务，停止任务仍使用原有取消流程。

## 管理入口恢复

QQ 菜单阻止管理员在当前入口移除自己的访问权限。另一处管理员入口可以管理被关闭的入口。网页工作台也提供“入口访问控制”，沿用管理员 Cookie、同源与 CSRF 验证，允许恢复全部聊天被关闭的状态；网页不会因为聊天来源被屏蔽而失去管理员登录能力。

使用相同持久版本与审核规则的 API 为 `GET/POST /api/admin/gateway-access`。网页保存需提交入口、预期版本和一次明确的更改；不允许请求任意 principal 或通过模型修改策略。

## 持久化与升级

schema 7 新增 `gateway_access_policies`、`gateway_access_inputs` 和 `gateway_access_audit`；schema 6 的账号、设备、会话、发件箱和个人设置保留。升级前备份数据库。回滚到 schema 6 程序必须同时恢复升级前数据库，不能让旧程序打开 schema 7。

新适配器的默认策略拒绝所有来源；接入时实现 `MessageAdapter::conversation_scope`、标识校验以及必要的首次引导白名单。不能直接按字符串外观猜测其他平台的群或用户，也不能绕过 `Gateway::route_allowed` 单独实现一套名单引擎。
