## 云端归档接线

新增窄接口 `ArchiveStorage` / `DeploymentArchive`，避免让 CloudJournal 冒充完整的上游 SessionResources，也不引入第二套任务或工作区权限。

- Cloud schema 25 增加 `cloud_archive_entries`，保存有身份约束的原文恢复副本与投影目录。
- 同一次迁移撤销已知 policy 2 的旧渲染动作，使用 Journal 保留的原文重新规划；保留隐私排除、Full 的取代证据、任务身份和未知操作状态，不把未来未知版本当作旧版本清除。
- 先保存并校验原文，再事务提交投影；确认成功后才更新热视图。未知提交结果阻止当前上下文继续使用。
- CloudJournal 的正常回合结算仍拥有主历史、任务及操作状态。恢复副本不触发工具、不重放任务，不承担操作恢复。
- `ReadContextArchive` 为会话绑定的只读工具，预算、游标和完整性沿用上游协议；不能用模型参数选择账号或会话。
- 每次读取复核真实用户、会话代次、个人记忆隐私 epoch 与有效期；跨会话引用不授权读取。新执行窗口仍通过原任务检索工具查询相关旧任务。
- 初始归档绑定已经装配的个人记忆 fence；装配与打开归档之间发生遗忘或上下文代次变化时拒绝接纳旧快照。
- 隐藏推理及不透明 provider block 不进入可回查副本；相应消息保护为不可归档候选。
- 已排除历史只有被活跃归档根明确引用时才重新进入恢复范围；清空、回退和遗忘不能凭旧引用扩大当前范围。
- 主会话自动压缩与手动 `/compact` 保留摘要式 Full；执行者继续使用原持久换窗策略。

CloudJournal 当前仍将完整 canonical 历史保存在会话 JSON 中。本轮降低的是模型视图的体积，未宣称完全解决宿主历史内存占用，也未测量真实 provider 的缓存命中率。

## 异步生命周期与消费确认

同步上游进程内 mailbox：投递成功不等于模型已处理，待处理结果在摘要和投影中受到保护。云端任务事件使用稳定 delivery ID；成功的模型消费另记诊断用途的持久回执，失败或重启后未消费的结果重新纳入保护。

这些回执只说明模型请求已成功消费对应输入，不代表任务验收通过、工具执行成功或 QQ 消息送达。Cloud 的持久任务、操作账本、取消、等待、资源占用和未知结果核实保持原实现。

已随回合结算保存的事件及消费回执可以冷重建。宿主若在结算前退出，原回合仍走 Cloud 的 RecoveryRequired 核实流程，事件输入保留在原受理记录中，不通过 mailbox 自动重放。

新增 `SettlementDue` 与 `HookStopped` 结果映射为中断，不当作完成；不因上游进程内收尾机制而自动重开执行。

审批专用回合继续只有 decide_approval、inspect_task、message_task 三个协调工具，不开放归档或设备执行能力。宿主临时只投影当前授权记忆与审批事实，结束后恢复普通聊天视图并隐藏协调轨迹；期间发生真实隐私截止变化时不恢复旧上下文，普通记忆更新则保留聊天连续性。

## 工作区身份

上游 resources 的工作区定位更新用于本机资源发现，保留其修复。远程执行器仍在每次请求核验冻结的规范路径、设备与目录身份；同路径被替换不会继承旧任务的写入资格。需要重新选择和绑定工作区时通过原授权入口进行。

本轮不新增自动重绑定，也不扩大跨设备、跨工作区或跨隐私范围的执行会话复用。
