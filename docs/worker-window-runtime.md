# 执行窗口运行契约（schema 26）

本轮实现对应 [换窗设计](design/worker-window-rotation.md)。这里只说明代码保证的行为；模拟联调不能证明真实模型的接班质量、缓存命中率、费用或生产可用性。Issue #7 按用户决定保持开放，真实调用与生产升级暂缓。

## 触发、接班与续跑

主助手继续摘要压缩。执行者的物理窗口可替换，任务和逻辑执行会话保持原 ID。

| 触发 | 接班后行为 |
| --- | --- |
| 宿主预算边界 | 核验最新权限、指令、设备和操作结果后继续当前任务 |
| 执行者 `request_window_rotation` | 同上；理由及短笔记可选辅助交接，不必平时维护长记录 |
| 主助手 `control_task(action="rotate")` | 默认进入 `window_ready`，完成交接但不启动工作模型请求 |
| 手动换窗且明确关联的主会话 goal 仍活跃 | 可以继续；在提交与启动边界重新核验关联 ID、状态及 token 预算 |
| 暂停、等待、取消、隐私失效或原操作未知 | 原有约束优先，换窗不授予额外执行权 |

`delegate_task(link_parent_goal=true)` 由宿主取得当前主会话的真实 goal ID；无有效 goal 时拒绝关联。省略或为 false 时不关联。执行者只有任务目标，没有独立 goal 控制器。同账号其他主会话的 goal、后来新建的 goal 或未完成任务本身不能代替该关联。

`window_ready` 中普通聊天和 `message_task` 补充要求不会启动旧工作。主助手显式 `control_task(action="resume", expected_revision=最新版本)` 才继续。重复请求切换已就绪且未工作的窗口直接返回现状，不消耗摘要调用。暂停或等待任务切窗保留暂停/等待及原定唤醒条件。

执行者主动换窗工具必须单独构成一批调用。宿主在派发前拒绝“换窗 + 其他工具”的整批请求，避免同批副作用与控制顺序不确定。

## 三种材料

1. **当前锚点**：激活时由宿主装配完整目标、约束、验收及保留的父级指令，连同当前任务状态、指令版本、新于摘要水位的消息 ID、近期原操作事实。代码不声称能自动理解并删除被自然语言替代的约束。材料装不下就等待，不静默裁掉必需要求。
2. **接班摘要**：用原执行者的账号模型路由发一个专用请求，输入是带来源的可见文本和调用引用，不含隐藏思考。`tools=[]`，且根本不安装工具派发器。正文只表示原执行者的理解，不能改变生命周期、权限、任务要求或验收。tool-shaped、空白、超长或非完整结束响应不作为合格摘要。
3. **历史入口**：窗口、轮次、原操作回执、父子消息和已保存摘要通过任务授权查询。新窗携带最近合格接班材料和一个工具结果预览，不复制全部 trace 或累积所有旧摘要。

摘要水位固定于生成输入；后到指令在激活时重新装配，不修改旧摘要来伪装覆盖。摘要中的引用是待核查的模型声明，验收仍要求已有产物和操作证据。

## 持久状态与崩溃边界

`agent_window_rotations` 保存意图 ID、来源任务/窗口/轮次、检查点哈希、指令水位、触发原因、原等待状态、摘要及状态、用量和候选目标窗口。状态为 `requested → summarizing → prepared → committed`，失效时 `aborted`。

- 任务进入换窗和接受换窗意图在一个事务中完成；版本冲突不会留下已接受的额外意图。
- 每任务、来源窗口至多一个待处理意图。摘要提交前持久记录 `summarizing`，同一意图不自动重复提交逻辑摘要请求。
- 超时、取消请求、模型失败或结果无法确定时使用事实和历史降级。重启打开 journal 时将遗留 `summarizing` 转为 `prepared / unknown_after_restart`，不重发请求。
- 候选执行器绑定在主助手控制锁之外准备，避免阻塞聊天控制。重核 principal、设备、规范路径和文件系统身份，持久预留目标窗口；再在短事务内提交当前窗口、排队任务绑定、轮次、接班帧和意图终态。
- 崩溃可能留下未激活的候选窗口记录；它没有任务执行权或副作用。已持久预留的候选会复用，原子提交不会产生两个当前窗口。
- 原工具独立结算，调用、窗口和执行器 invocation ID 不迁移。已确认提交且可追踪的运行工具可以跨窗继续；未知状态、404 或不可认证的原结果必须先核实。设备修改占用直到真实结算才释放。

摘要辅助请求由原 Runtime 持有，使用后台并发额度和账号每日模型请求额度，受宿主关闭和取消控制。它不持有普通聊天的执行门。无法取得后台槽位时保留原意图等待；摘要不可用不影响事实降级。普通工作请求额度耗尽时进入持久等待至下一个 UTC 配额日，或由主助手显式恢复后重新核验。

## 预算与用量

`RuntimeLimits` 默认值：

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `worker_window_tokens` | 48000 | 同时受模型上下文容量限制 |
| `worker_reserve_tokens` | 8000 | 输出、交接与估算误差余量，最多占有效窗口一半 |
| `worker_handoff_tokens` | 1200 | 专用摘要输出限制，范围 64–8192，实际不超过窗口四分之一 |
| `worker_handoff_seconds` | 30 | 专用请求等待上限，范围 1–120 秒 |

每次工作模型请求在出网前计算完整 `ModelRequest`（含系统、工具 schema、消息及协议字段）的保守字节估计；它不是 tokenizer 或精确账单。观察到的 provider 用量只向上校准。边界估计包含实际请求测得的固定前缀，接近阈值时添加一次预算提醒。

工作请求的实际输出上限也限制在有效预留空间内，并取调用方或模型配置中更小的上限；账号模型较大的默认输出不能绕过窗口容量。新窗口首次完整请求仍放不下时，任务进入可解释的 `waiting_external`；没有请求、换窗和再请求的空转。摘要本身另有输入和输出预留，不够则降级。

`agent_window_budget` 保存估计、校准、可得的输入/输出/cache 用量及未知样本数。Anthropic 输入统计包含分别报告的缓存读写；OpenAI 输入已包含缓存时不再次相加。未知值不记成零。摘要记录独立标记用途、原轮次、可得 token 使用及完成请求延迟；失败/未知请求没有可确认费用。它们不能据此算出真实价格或缓存效果。

## 工具契约

主/执行者均可通过 `inspect_task(task_id, ...)` 读取授权任务：

- `view="overview"`：当前状态、关联主 goal、指令水位、最近 8 个窗口、最近 4 份交接、当前预算和操作预览；完整窗口目录继续用 `windows` 分页。
- `view="search", query?, after=0, limit=12, window_id?, filter?`：有界词面检索。`filter.source` 为 `operations`（默认）、`messages` 或 `conversation`；支持适用来源上的 `tool / call_id / status / path / direction` 组合。
- 每页扫描最多 64 条操作/消息，或当前所选窗口的 16 条可见对话预览；命中最多 32 条、总览输出最多 24 KiB。即使本页没有命中，仍须沿 `next_cursor` 和 `has_more` 继续。对话搜索明确标记只检索预览，不能将裁剪后的无命中理解为完整正文不存在。
- `view="detail"`：`detail.source` 新增 `handoff` 与 `task_message`；沿用 `offset / chars / version` 的 Unicode 安全分段和版本冲突拒绝。对话详情引用需在顶层带来源 `window_id`。

所有入口重核任务可读性及隐私范围。操作详情绑定该任务，历史窗口绑定该逻辑执行会话；同账号显式复用会话本来就允许读取其共享执行上下文，其他用户、设备、工作区或受众不能静默继承。任务历史不会整批写入长期个人记忆。

## 验证与保留边界

具体命令和结果见 [本轮验证](worker-window-verification-20261024.md)。工程验证使用模拟模型与真实本地执行器，包含真实子进程强制终止；不调用付费模型、不改生产数据库。

当前检索是词面匹配和显式引用，没有向量检索或自动历史研究模型；token 预算是保守估计，模型语义接班、成本及缓存仍需另行真实模型评估。旧窗口记录没有自动垃圾回收，摘要失败时可能增加接班者的检索量。这些边界在 PR 和 Issue #7 保留，不以模拟测试代替上线验收。
