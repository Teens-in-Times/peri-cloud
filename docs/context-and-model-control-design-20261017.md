# Peri 跨设备上下文、模型接入与渐进式 Skill 设计

状态：待实施方案，2026-10-17。记录本轮用户草案及后续“设备技能先名称、切换后用途”的决定。

本文细化 `memory-and-skills-proposal-20261017.md`。旧文中的范围、来源、删除、权限要求继续适用；本文采用有容量上限的事实快照，不把向量检索作为基础依赖。网页重排和连接检查是独立交付；本文的模型目录、自动切机、分层记忆与自省尚未实现。

## 1. 用户看到的产品

- 聊天入口：QQ 等消息适配器，负责接收、呈现和交互，不拥有另一套 Agent。
- 云端主控：推理、会话、模型路由、记忆、技能与任务调度。
- 我的设备池：账号有权使用的执行器；可按职责命名，例如东京主控机、北京构建机、本地 Windows。
- 会话：当前目标设备、工作目录、工具权限、任务和历史的容器；同一设备可以承接多条独立会话。
- 模型与 API：用户管理连接和模型，再给主力、自省、审查三个角色分配模型。
- 记忆：事实和参数；技能：方法和步骤；历史：原始过程。三者不会互相假扮。

默认 QQ 完成选择、查看、编辑、确认和回退。网页提供拓扑和批量管理。密钥录入使用不会把密钥发送给模型的专用安全表单或本地导入；不要求用户把明文密钥发进群聊。

## 2. 统一模型与 API 管理

当前代码 `models.rs` 是“管理员在 host.json 声明供应商 + 每账号一个模型/密钥”，尚不是可管理多个连接与模型的目录。新增模型先沿用已有 OpenAI 兼容适配，不把未经实现的协议标成支持。

建议实体：

| 实体 | 管理内容 | 关键约束 |
| --- | --- | --- |
| ApiConnection | 名称、协议、API base、SecretRef、启用状态、revision | 账号隔离；密钥只写不回显；地址变更须重新确认凭据归属 |
| ModelEntry | connection_id、真实 model_id、展示名、上下文和输出上限、能力声明 | 手动录入是基础；发现列表是可选提示；能力声明不等于验证成功 |
| ModelRoute | primary / reflection / guard 的 model_entry_id 和预算 | 默认显式分配；审查失败不能静默改为放行 |
| ModelProfile | 一轮冻结的路由版本、模型参数、提示词版本 | 正在执行的轮次不随页面编辑中途换模型 |
| ConnectionCheck | 时间、认证结果、协议支持、错误分类 | 检查可能产生提供商调用费用，需按钮明确触发；禁用后不再新建调用 |

密钥只进后端凭据仓库；审计和导出使用引用与脱敏状态。数据库备份不能默认包含可解密密钥；加密主密钥与数据库分开持有，复用现有环境变量密钥迁移也需要有回滚步骤。

新增 endpoint 不能只做 URL 格式检查：默认只接受 HTTPS、无 URL 用户名密码/查询串，校验每次连接与重定向的最终目标，拒绝云元数据和未授权内网地址；受信的本地模型地址由管理员显式放行。DNS 重新解析不能绕过检查。模型和聊天内容均无权修改该策略。

主力、自省、审查是职责，不硬编码 Flash 或某一家产品。审查可以低延迟，但不能承诺所有提供商调用都毫秒级。统计三个角色各自的 token、费用、耗时和失败率；后台有独立并发与日预算，不能抢光前台配额。初始不配置后台角色也可正常使用主力 Agent。

## 3. 三层 Skill 披露：名称 → 用途 → 正文

这是本轮确认的呈现规则：

| 时点 | global / fleet | capability / device |
| --- | --- | --- |
| 会话起始 | 名称 + 一句话用途，受目录预算约束 | 设备专属只给名称 + 所属设备，不给用途；能力技能按已知设备归类 |
| 切到匹配设备 | 保持已知目录；有变更则追加目录版本 | 返回适用技能的名称 + 用途，不自动加载全部正文 |
| 决定使用 | `load_skill(skill_id, version)` 读取正文 | 同样按需读取；执行前再次核对目标设备、能力和权限 |

名称用于发现，用途用于选择，正文用于执行。名称要表达动作和对象，如“服务滚动更新”，避免“常用工具”“脚本1”这类缺少用途就无法选择的名称。资源文件按引用再读取，不能因为加载一个技能就递归读取整个目录。技能数量超出预算时，返回分页或 `find_skills`，不能无界堆积名称。

底层使用稳定 skill_id 和不可变版本。同名技能通过设备归属与 ID 区分；展示名不要求把机器 IP 硬编码进名称。`load_skill` 是固定工具，不把每个 Skill 变成一个动态 tool schema，以保持工具列表稳定。

`affinity` 是适用范围，不是授权：

- global：通用流程，不依赖具体设备。
- fleet：涉及多机接力的流程，使用角色参数定位机器，不写死设备地址。
- capability：需要 OS、软件或功能；能力指纹来自受信执行器的有时效观测。
- device：确实只适合指定设备，显式记录 device_id。

SKILL.md 保持标准 `name` / `description`，Peri 扩展放在 namespaced metadata 中；未激活设备时 description 仍存在于存储，只是不披露给模型。服务端绑定 owner、启用状态与权限，不能信任文件自己声明的归属。

“动态挂载”先实现为逻辑可用目录；不把东京主控的本地 Skill 文件冒充目标设备的文件。脚本要在目标执行器上运行，经原有工具链和 PermissionMiddleware；加载技能本身不授予执行权限。

## 4. 四层事实快照

| 范围 | 服务端绑定 | 初始预算建议 | 生效方式 |
| --- | --- | --- | --- |
| USER | 当前账号；私聊可见范围 | 1,200 Unicode 字符 | 会话开始冻结；之后修改以尾部更新帧生效 |
| FLEET | 当前账号可见的设备池及成员版本 | 1,500 字符 | 初始职责与拓扑摘要；设备增删、撤销和实时状态另外查询 |
| DEVICE_ENV | 当前账号与明确 device_id | 2,000 字符/设备 | 选择或切换设备时追加相应版本 |
| CONTEXT | device_id + 规范化目录 + 仓库身份 | 文件和摘要双重限额 | 执行器读取项目规范；只读注入，不能覆盖系统规则 |

字符用于用户理解，存储同时限制 UTF-8 字节，注入同时限制 token。进度如 `1,420 / 2,000 字符 · 71%`；85% 发出整理提示，100% 拒绝超额提交并保持原数据。容量告警不是强迫模型删除重要事实的命令。

数据库按原子条目存储，快照可用 § 分隔展示。每条含稳定 ID、内容、来源、scope、revision、状态和时间。分隔符只是视图，不拿分隔符或自由文本作为并发寻址机制。

本阶段设备池是账号的设备集合；引入共享 pool_id 前必须有成员与撤销契约。项目不能只靠 workspace_hash 授权：同路径不同机器、仓库更换和路径复用必须隔离。FLEET 中的 IP 是事实资料，不是实际连接配置；密钥、SSH 参数、设备令牌永远不作为记忆载荷。

群聊白名单不意味着可公开注入 USER 私人记忆。应按会话可见范围生成快照；移除群或成员后，后续读取、候选审批和后台任务同样重新检查权限。

## 5. 稳定前缀与追加上下文

目标是保持同一会话版本内的前缀稳定，不能保证供应商 100% 缓存命中。缓存还受模型、有效期、最小长度、工具定义和供应商实现影响。[Claude 缓存文档](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)。

建议分层：

1. 版本化系统规则：职责、权限边界、工具规则、如何解释环境帧；不含当前时间、活动设备或临时状态。
2. 会话起始快照：USER/FLEET 及可见技能目录，冻结其版本与可见范围。
3. 追加事件：设备切换结果、记忆提交回执、Skill 目录更新、项目上下文。
4. 常规对话与工具结果。

偏好或 FLEET 会变，因此“全局不变”应理解为“在本次会话版本内冻结”，不能把用户资料永远锁死，也不能每轮原地重建 System Prompt。真正的账号撤销、权限变化和资料删除优先于缓存优化。

不能只检查 System Prompt：工具列表、工具参数 schema 和提示词贡献器的排序也必须稳定。当前 `run_personal_turn` 每轮拼接 USER 文本，需要改成版本化初始快照与追加更新帧，而不是直接在旧代码里不断加更多 prompt 字符串。

每个环境帧带 `frame_id`、device_id、binding_epoch、snapshot_revision/hash、skill_catalog_revision、context_generation 和模式。尾部横幅可读，但代码依据结构化字段判断执行目标，不能依赖 AI 读懂一句警告。

A → B → A 时，仅当 A 的最新帧仍在**实际发送给模型**的上下文中、可见范围有效、版本相同，才返回指针。指针用稳定 frame_id；Turn #X 可显示但不作为唯一定位。压缩、截断、换模型或版本变化后重发完整快照。不能只检查数据库历史是否曾经发过。

常规压缩产生新的上下文代次，保留活动设备的最新快照、未决任务和跨机对比结论；归档非活动帧并清空失效指针。审计原文和原始 tool-call/result 配对保留；不原地改写账本。删除私人记忆时，允许重建上下文，不能让缓存目标阻碍删除语义。

## 6. 自动切设备：切执行绑定，而不是 cd

固定的控制工具：

- `list_devices`：账号可见的设备、名称、职责、最后检查时间；登记状态与在线状态分开。
- `switch_device(device_id, workspace?)`：目标必须可见，目录必须在目标设备验证。凭据、endpoint、SSH 参数不接受模型输入。
- `load_skill(skill_id, version)`：按权限和适用设备加载指定正文。

自然语言“去服务器 B 看看”由 Agent 选择工具；用户 `/设备` 或菜单选择走同一控制服务。名称重名时向用户列出完整选项，不猜设备。手动切换对尚未派发的下一步生效；已发到 A 的操作仍归 A，不重放到 B。

在线切换事务：

1. 捕获当前账号、会话、turn 和 binding_epoch，验证目标归属和撤销状态。
2. 检查旧设备工具调用、审批与未确认执行结果。无法证明确实结束则返回 busy / needs_attention；切换操作不能隐式重放或取消它们。
3. 认证目标身份、平台与连接，验证和规范化工作目录，准备新的执行 segment。
4. 以 CAS 提交新 binding_epoch 和活动 segment，持久化切换事件；失败保留原目标。
5. 对后续工具派发原子发布新执行绑定，追加 `[EXECUTOR SWITCHED: A → B]` + 环境快照 + 名称/用途目录。
6. 前台可用后再提交自省候选任务，后台失败不回滚成功切机。

`FrozenSession` 保持单个执行 segment 内不可变。引入会话级活动绑定和不可变 segment 链，不能悄悄改写已经用于审批、恢复与任务归属的 device_id。Agent 的历史连续，审批仍绑定各自的 segment、设备、turn 和工具输入。权限模式遵循已有用户选择与规则，切机不能自动升为允许全部。

同一响应若包含 `switch_device` 和 Bash 等并行调用，必须先识别并拒绝混合批次，要求先切换、再发下一批；所有普通工具批次捕获固定 epoch。不能让完成先后决定某个命令落到 A 还是 B。

现有 `CloudAgent` 持有固定 RemoteSession，工具和 cwd 在运行开始时装配。实施时应在原 loop 的工具分派/模型请求边界增加受控绑定服务，或让控制结果返回 Runtime 续跑同一会话的新 segment；不能在普通工具里递归启动另一个 Agent loop。需先选定一种方式并写状态迁移测试。

离线模式：明确返回 `offline_snapshot` 和快照时间；**不提交活动执行绑定**。可以展示 B 的历史事实和技能目录，但不能声称已切到 B，更不能把 B 的后续命令落在仍在线的 A。建议单独 `inspect_device` 或显式 `mode: inspect`，避免一个 success 字段混淆查看与执行。

## 7. 记忆工具：显式写入，允许冲突恢复

主要动作仍是 `add / patch / remove`，强制 scope；device 必须传 target_device。owner 从已认证会话捕获，fleet 必须检查设备池成员权限。patch/remove 使用 item_id + expected_revision；后台也必须遵守 CAS。

“只写不读”适合常态热路径，不应成为绝对接口限制。压缩后、编辑非活动设备或发生冲突时，客户端可能没有最新快照。处理方式：写入成功返回新版本/容量/必要更新帧；冲突返回有界的最新可见快照，并允许专用恢复读取。不能让模型拿旧上下文盲写，更不能用模糊全文替换覆盖其他任务的更新。

所有变更带来源；自动整理不把猜测升级为事实。用户明确的“忘记”写 tombstone，后台旧候选不能将其复活。可选本地 MEMORY.md 是只读导出镜像，云端为真值；同步失败不阻塞写入，不接受修改镜像绕过审核。

## 8. 自省、审查与技能晋升

双锚点保留：设备 segment 已结算后切机，以及无活动工具/审批时静默约 10 分钟。计时基于最后受理的用户活动，噪音消息、旧消息重投和网页刷新不触发提炼。

后台任务持久化 owner、来源切片、设备 epoch、可见范围、模型路由版本和幂等键。重启可恢复，重复事件不重复生成；提交前检查来源是否仍可见、相关记忆是否已删除、配额与最新 revision。

后台模型初期只生成候选条目/Skill 草稿，无远程命令和任意网络工具。高风险写入 pending；审核服务不可用继续 pending。普通低风险自动事实是否可直接提交，作为显式用户开关，默认草稿。群聊卡片只提示数量和适当摘要，私人候选在私聊处理。

“三问自省”：这是否耐久且有来源？是环境事实还是可复用流程？与现有内容是否重复或矛盾？可以回答“没有值得保存的内容”。

规则先做密钥/令牌检测、路径资源约束、权限和结构校验，再由小模型辅助识别语义风险。小模型不能授予权限或证明内容绝对安全；不承诺毫秒级外部推理。未知 IP/URL 不是一概恶意，已授权机器拓扑可能含新地址；应结合来源、设备登记和变更意图判断。误报可以查看差异、拒绝或确认，不能静默丢弃用户资料。

Skill 生命周期：`draft → validated → pending/approved → immutable version → active → deprecated/revoked`。先 device，后 capability 是合理默认；相似度 0.85 只能召回候选，跨模型/语言不具统一阈值含义。晋升还需参数化检查、至少两个设备上的成功证据、能力前置条件、差异与人工确认。向量可选，绝不成为记忆写入或正常执行的硬依赖。

`CONTEXT.md`、导入 Skill、命令输出和记忆均是有来源的数据，不获得系统指令优先级。SYSTEM Prompt 的编辑独立于记忆工具：预览、版本、差异、回退，默认下个会话版本生效。

## 9. QQ 操作模型

- `/设备`：当前目标、完整设备选项、检查连接、切换；成功后只发一条简明回执（设备 + 工作区）。
- `/技能`：通用、跨机、当前设备、其他设备；其他设备初始只列名称，点选再查看用途/版本/正文。
- `/记忆`：我的、设备池、当前设备、选择其他设备；容量、条目、来源、编辑/忘记、候选箱。
- `/模型`：连接列表、模型目录、三角色分配、测试结果和用量；显示密钥状态，不回显密钥。
- `/提示词`：当前版本、查看、预览修改、启用下个版本、回退；不和 USER 记忆混在一个输入框。
- `/待办`：审批与后台候选分组；接受前展示精确差异，动作关联唯一候选 ID 和 revision。

官方 QQ 按钮和个人 QQ 文本编号共享完整语义；分页不截断选项名，旧菜单不能覆盖新版本。机器 ID 可在详情显示，常用列表用可区分的完整名称；全程不依赖网页才能处理日常任务。

## 10. 实施顺序和验收

1. 网页层级与账号可见拓扑、设备显式检查：独立交付，不改运行绑定。
2. API 连接/模型目录、凭据边界与角色路由：先手动管理，再提供可选发现和测试。
3. 会话/执行 segment 和 binding_epoch：手动与 AI 切机共用服务；先打通 A → B → A 真执行。
4. 分层有界记忆和三级 Skill 目录：以相同会话的上下文帧串起来；接入固定 load_skill。
5. 提示词版本和压缩代次：验证前缀稳定、指针失效恢复、遗忘和群聊隐私。
6. 双锚点自省与候选箱；最后再做受控晋升、可选语义去重。

关键验收：

- 两台真执行器，B 离线、身份不符、目录不存在、A 有未确认结果均不能出现误执行或伪成功。
- 同批切机 + 写入、迟到审批、切机中撤销、并发用户切换、服务重启各有归属断言。
- A → B → A 哈希相同可复用；压缩移除 A 帧后必须重新披露；模型只看到当前有权访问的技能。
- 切换前无设备技能用途；切换后有匹配用途但无正文；load 后只有选定正文/资源。
- 记忆容量边界、Unicode/字节/token、多写冲突、忘记后后台复活、群聊私密隔离均测试。
- 三个模型角色分别计费限流；审查超时保持 pending；错误日志、模型上下文和导出不含密钥。
