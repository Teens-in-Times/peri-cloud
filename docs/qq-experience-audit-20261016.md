# QQ 优先的 Peri 交互审计与 Hermes 对照

审计日期：2026-10-16。目标：QQ 承担日常操作，网页作为可选工作台和初次账号授权入口。

Peri 生产代码基线：独立仓库 Teens-in-Times/peri-cloud，v0.4.0，`7b797fdbab8246feb293fae20872c1f5b93de285`。实际修改位置为本文件所在仓库。旧 G 盘工作树使用另一套状态结构，不能直接覆盖东京的 schema 6 数据库。

## Hermes 借鉴结论

研究的是固定源码快照 `275b15fc35193b8ddafcf16776539c04587e6ccf`，没有运行 Hermes 或接入其服务。以下结论不是对其全部功能的比较。

| 观察 | Peri 的选择 |
|---|---|
| [QQ 接入与语音](https://github.com/NousResearch/hermes-agent/blob/275b15fc35193b8ddafcf16776539c04587e6ccf/website/docs/user-guide/messaging/qqbot.md)：官方接口支持群聊 @、私聊、图片、附件和语音转写 | 日常流程优先在 QQ 完成；附件与语音列为后续完整输入链路，不能只显示“支持上传” |
| [审批按钮与摘要](https://github.com/NousResearch/hermes-agent/blob/275b15fc35193b8ddafcf16776539c04587e6ccf/gateway/platforms/qqbot/keyboards.py)：命令、目录和超时信息集中展示 | 借鉴就地决策；保留精确操作的一次审批，提供 QQ 原生按钮、文字命令和完整参数分页 |
| [忙时输入](https://github.com/NousResearch/hermes-agent/blob/275b15fc35193b8ddafcf16776539c04587e6ccf/gateway/run_busy.py)：支持补充、打断与 FIFO 排队 | 学习语义区分；产品默认应稳定，避免让用户先理解忙时模式配置 |
| [进度表达](https://github.com/NousResearch/hermes-agent/blob/275b15fc35193b8ddafcf16776539c04587e6ccf/gateway/run_turn_progress.py)：生命周期与消息展示分开 | 状态只回答“在哪、在做什么、等谁”；正常聊天不灌入推理与工具日志 |
| [QQ 发送实现](https://github.com/NousResearch/hermes-agent/blob/275b15fc35193b8ddafcf16776539c04587e6ccf/gateway/platforms/qqbot/adapter.py)：分段发送，私聊 typing；部分异常会重试 | 不把私聊 typing 当成群聊保证；保留 Peri 的持久序号和未知送达不重放，完整结果可主动取回 |

“做得更好”应以具体任务是否完成衡量：用户能否在 QQ 直接作答、核对完整参数、从丢失的消息恢复结果；重复或过期按钮是否不会产生额外执行。不能仅凭按钮外观判定。

## 用户只需要理解的对象

1. **Peri** 是同一个助手，QQ 是主要会话窗口。
2. **执行设备** 是这次任务操作的电脑或服务器；**工作区** 是它使用的目录。
3. **当前任务** 有运行、等待回答、等待审批、取消中、需要确认和空闲等状态。
4. **个人设置** 属于账号，跨设备共用，下一轮对话生效。
5. **已保存结果** 是原任务的输出，查看它不会重新运行任务。

群聊内，每个成员使用自己的绑定身份与当前选择。群聊文字消息需按 QQ 官方接入方式 @机器人；按钮回调仍由后端核对真实点击者。

不向普通用户暴露 transport、executor binding、provider endpoint 或 journal 等内部概念。“已登记设备”只表示登记成功，不能替代在线连接验证。

## 云 Agent 的一致模型

`账号 → QQ 路由（Bot + 会话位置 + 真实用户） → 当前会话（设备 + 工作区） → 任务 → 等待中的交互请求 → 待送达消息`

- 路由归属、会话选择和设备授权共同决定可操作范围。
- Agent 循环和原有权限中间件决定何时需要审批；QQ 与网页只呈现、提交同一个 broker 请求。
- 提问草稿属于请求，答案不另起一次任务。每次改动递增版本；旧按钮拒绝修改新草稿。
- 按钮令牌不携带信任，必须匹配用户、路由、会话、有效期和请求版本。
- 工具执行是否成功、消息是否送达是两件事。未知送达不触发重执行，用户可通过新消息取回保存结果。
- WireGuard 与 SSH 反向连接是同一设备的连接路径；路径切换不改变任务、会话或设备身份。

## 本批落实的 QQ 能力

| 操作 | QQ 入口 | 语义 |
|---|---|---|
| 设备与工作区、权限 | `菜单`、`/设备`、`/工作区`、`/权限` | 复用既有授权与设备浏览能力 |
| 任务状态 | `/状态`，兼容 `/status` | 展示设备、工作区、权限及真实等待阶段 |
| 停止任务 | `/取消`、`/停止`、`/stop` | 请求停止，未确认前不声称执行已停止 |
| 单选、多选、连续多题 | 选项按钮、`/回答 内容`、`/回答 1,2` | 逐题回答，多选点“提交本题”；只有完整作答后恢复原循环 |
| 重开问题 | `/问题` | 打开当前题目，保留多选草稿；选项多时可翻页 |
| 不提供答案 | “暂不回答”按钮 | 显式拒绝，不伪造空答案 |
| 完整审批或题目参数 | `/详情 请求短码 [页码]` | 只读分页，不能隐式授权或提交 |
| 文字审批 | `/允许 短码`、`/允许一次 短码`、`/拒绝 短码` | 与按钮使用同一请求和一次授权边界 |
| 找回长结果 | `/结果 [页码]`、菜单“查看结果” | 从当前选中会话取最近终态结果，分页固定原任务；不调用模型 |
| 设置入口 | `/设置` | 同时提供按钮入口及文字用法 |
| 记忆 | `/记忆 [页码]`、`/记住 内容`、`/记忆 设置 内容` | 查看、追加或替换账号记忆 |
| 偏好 | `/偏好 [页码]`、`/偏好 设置 内容` | 查看或修改账号指令 |
| 清空个人数据 | `/记忆 清空`、`/偏好 清空` | 确认按钮绑定数据版本；并发修改后旧确认失效 |
| 用量 | `/用量` | 复用账号计量，标明 UTC 日界 |
| 模型 | `/模型`、`/模型 模型名` | 使用已绑定的同供应商个人密钥切换，下轮生效；不通过聊天录入密钥 |

长回复采用 1200 个 Unicode 字符预览和结果分页，这是 Peri 的展示策略，不宣称是腾讯平台的硬性字符上限。原文完整留存在原任务。按钮不可用时可用 `/选 数字` 或相应文字命令完成日常操作。

可选网页同步展示相同的等待阶段、实际问题表单和保存结果。题目使用单选/多选/文字控件，未填完不能提交；关闭表单不等于拒绝。请求超时、任务取消或通道失效通过共享协议的 `Cancelled` 表达，只有明确拒绝才使用 `Rejected`，不会告诉 Agent“用户拒绝回答”。退出账号时清除表单和结果详情。网页未承担额外的授权权威。

## 仍需完成的产品闭环

本批没有把以下能力冒充为已交付：

- **运行中切换设备与补充/排队/停止语义**：旧工作树中已有相关改动，但独立生产基线尚未合并。必须对 schema 6 的多用户、配额、模型和菜单能力做兼容移植；不能发布旧 schema 5 写入器。优先级最高。
- **会话与历史选择**：当前 `/结果` 面向当前选中会话；切换设备后，需要 QQ 内的任务列表与历史会话入口，不能只在网页或数据库中留存。
- **文件和语音**：接收、引用、处理回执、输出文件下载，均需绑定账号/任务并验证 QQ 实际权限。超长报告应支持文件交付，分页是基础恢复入口。
- **长任务通知**：完成/失败/需要输入应给可恢复入口，避免刷屏；超出平台回复窗口时不能假装主动推送必达。
- **定时任务管理、设备加入/撤销和恢复指导**：需要 QQ 内明确的状态、撤销与审计入口。
- **首次身份与密钥设置**：浏览器的人类授权仍有必要；QQ 提供准确的一次性入口，完成后日常使用不反复要求打开网页。

建议下一批先完成运行中补充与设备切换，再做任务列表/历史恢复，最后补齐媒体与定时管理。统一术语和状态机后再增加命令，避免继续增加用户需要记忆的模式。
