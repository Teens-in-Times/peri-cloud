# 主助手自动审批执行任务

实施状态：schema 20 接入执行任务的主助手审批代理。主助手自己的直接操作仍沿用既有权限模式；本阶段不改变 OAuth 人工授权或账号、设备、渠道准入。

执行 agent 的敏感工具调用仍进入原 PermissionMiddleware。中间件向 WorkerBroker 请求决定；WorkerBroker 将完整参数与任务要求交给主助手的独立审查回合，返回一次性批准或拒绝。执行器只验证运输、绑定与调用身份，没有新增本地审批。

## 独立审查回合

审查使用原 Agent loop、主会话的模型选择与身份，每次最多一次语义迭代，工具目录为空，整个请求最长 90 秒，最多四个并发审查，并计入用户模型请求额度。它不取得主会话 turn_gate，不修改前台聊天历史；前台可继续聊天。它是主助手的独立审查调用，不是另一个长期运行的执行 agent。

输入包括当前任务目标、约束、验收要求、保留的主助手补充要求、真实设备与工作区、当前轮次，以及完整调用参数。输入超出容量时不做部分批准，也不静默裁剪旧要求。模型按固定规则返回结构化决定、删除可能性、简明理由和通知正文；不采集隐藏思考。

调用参数、工作笔记和工具内容是待检查的证据，不是宿主指令。审查不增加人工确认门槛；任务内的命令可以自动批准，与用户要求冲突或越出任务范围时可自动拒绝。模型错误、超时或失效请求不能降级为自动批准。

## 精确归属与版本

每个请求持久保存可信用户、任务、父主会话、执行窗口、运行轮次、完整参数、指纹、最新补充消息序号及期限。决定只能消费一次。审查前后及原生工具调用受理前重新核验归属、当前权限边界和指令水位；新要求、暂停、取消、清空或隐私变更使旧决定失效。

主助手补充消息的持久序号是 instruction_version；inspect_task.status 返回当前值，approvals 视图返回每次决定所依据的值。原生写入意图的数据库更新还核对当前水位与匹配的完整审批参数，防止审查和真正受理之间沿用旧要求。

每个窗口单独记录完整输入已读水位。换窗不会继承旧窗口的“已读”；如果最新摘要未包含所有保留要求，执行 agent 必须通过 messages 分页加载遗漏内容后才能继续调用工具。宿主不能仅凭旧消息已应用就认为新窗口记得旧约束。

执行 agent 使用原权限中间件的 Default 策略向代理请求敏感工具决定；主助手原有权限模式不变。执行任务不会借继承的“全部允许”模式跳过删除通知。

## 删除前通知

主助手审查整个操作的语义，包括嵌套脚本、解释器、数据库操作和替换内容，不能仅依赖命令名。宿主对任意 Shell、Write、Edit 另采用保守判断：这些操作可能移除或替换已有内容，必须先通知。读操作不因此产生额外通知。

通知正文是主助手生成的简短 AI 文字；不展示原始工具参数或隐藏思考。通知先进入原持久发件箱，核验账号、入口、任务、隐私、指令版本和期限。只有确认投递成功后，权限中间件才取得批准决定并继续工具派发。通知不是人工审批，无需等待点击。

明确被拒绝或抑制的投递不表示已通知，操作仍不执行；可在后续恢复后重新审查。投递结果未知时保留原发件记录，不自动重发，也不重新运行模型来换一条通知绕过未知结果。此时任务保留等待状态，必须核对原投递事实；当前没有将未知投递强行视为成功的工具。

## 中断与恢复

自动审批无法完成时，任务保存有界的外部等待，释放执行轮次，避免反复即时调用模型。重启后旧决定不会授予新轮次权限；宿主先核验原操作是否受理，未派发的操作在后续轮次需要新审查。已经提交的操作按原 invocation_id 查询，不能重新提交。

执行 agent 的 AskUserQuestion 也通过代理转给主助手，保留原问题与选项并持久等待父消息。主助手自己解决或继续询问用户，再用 message_task 回复；无需让执行回合一直持有人工问题的进程内等待。

## 查询

inspect_task(view="approvals") 返回有界分页：请求 ID、执行窗口、轮次、参数指纹、所依据的指令版本、期限、状态及主助手决定。view="detail" 配合 source="approval_input"、请求 ID、offset/chars 可分段读取完整参数，并用 version 核对读取期间内容没有变化。审批历史不能当作新的授权。
