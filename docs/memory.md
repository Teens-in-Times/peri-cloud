# 分范围记忆与上下文

记忆在云端按账号保存，以条目为真值。回复偏好、长期事实和原始会话历史分别管理；调度器不保存记忆，也不依赖记忆实现。每次普通或定时任务开始时，云端使用同一入口读取当前有效版本。

本版开放 USER（个人资料）、FLEET（本人设备池）、DEVICE_ENV（显式设备 UUID）三个范围，所有范围都属于当前账号且只在私人入口使用。模型访问、新增和修改设备记忆时，每次重新校验归属和未撤销状态；设备目录不含运输配置，登记不代表在线。CONTEXT 仍明确不可用：现有工作区只有执行目录身份，没有独立仓库授权绑定，不能把目录字符串或路径哈希当成项目权限。没有后台自动提炼或向量服务依赖，模型不应自动把推断、工具输出或凭据存入记忆。

## 保存、更正与忘记

每条记忆包含稳定 UUID、不可变 scope、独立 revision、事实/决定类型、正文、置顶状态、可选有效期、创建/更新时间与来源。来源由入口捕获：网页、QQ 确认、Agent 当前会话/任务或旧版导入；请求不能指定账号与伪造模型来源。更正沿用条目 ID，旧 revision 不能覆盖并行修改。

账号另有 generation。新增必须提交刚读取的 generation；任何记忆变更都会推进它。因此，删除前生成的添加确认不能在删除后补交。新增 request_id 重试只返回同一条目的当前状态，已删除 ID 不能复活。用户查看最新版本后可以明确重新添加一条事实。

遗忘会在一个事务中清除条目正文、检索内容与 FTS 行，只保留 ID、来源引用、版本和操作摘要作为 tombstone。审计表不保存历史正文，索引重建只读取仍有效的条目。聊天记录、已发送消息、SQLite 历史页/WAL 与既有备份有各自的生命周期；本操作不宣称清除了这些历史副本。恢复旧备份会恢复那个时间点的状态，不能将它当作保留最新删除结果的恢复。

遗忘与更正同时推进账号 `privacy_epoch`。模型视图遇到隐私版本变化、记忆到期或设备目录变化时，保守排除截止点之前的整段上下文（包含旧工具调用/结果、AI 转述及压缩摘要），补发当前授权快照。原始审计记录及工具配对保留，截止点独立于通用 flags，回退不能恢复被隔离的内容。代价是更正/遗忘可能使助手失去此前任务的对话细节；已在途或已发送到供应商的请求无法收回。

过期资料不会进入 Agent 快照、SearchMemory 或 GetMemory。网页和 QQ 的管理视图仍显示它，方便重新确认、更正有效期或忘记；过期资料继续占用存储额度。

## QQ

个人资料仅在适配器明确标记的私聊使用。群聊及范围未知的入口不注入个人偏好或记忆、不注册记忆工具，也不能通过控制命令查看私人正文。会话的私人可见性持久保存；含私人资料或来源未知的旧会话不能通过恢复历史进入群聊，升级后的旧群会话请 `/new` 开始空白上下文。群历史列表也不披露私人会话。网页独立会话是已认证的私人入口；网页操作群会话时仍沿用该群会话的可见范围。

| 操作 | 命令 |
| --- | --- |
| 列表、翻页 | `/记忆`、`/记忆 2` |
| 新增 | `/记住 内容` |
| 关键词搜索 | `/记忆 搜索 小蓝` |
| 原文与来源 | `/记忆 查看 UUID` |
| 更正正文 | `/记忆 修改 UUID 新内容` |
| 置顶 | `/记忆 置顶 UUID`、`/记忆 取消置顶 UUID` |
| 有效期 | `/记忆 期限 UUID 2026-12-01T18:00:00+08:00`，或 `永久` |
| 遗忘 | `/记忆 忘记 UUID` |
| 回复偏好 | `/偏好`、`/偏好 设置 内容`、`/偏好 清空` |

可在命令后选择范围：`/记住 设备池 小蓝是测试机`、`/记忆 设备池 搜索 小蓝`、`/记住 设备 UUID Python 3.12`、`/记忆 设备 UUID`。不指定时为个人资料；设备 UUID 可从 `/设备` 查看。所有查看、更正、期限、遗忘命令及分页均保留所选范围。

记忆变更展示完整内容、范围和确认按钮。按钮绑定账号、聊天路由、预期会话、条目 revision 或账号 generation，并有原有菜单期限；修改后旧确认失效。QQ 管理操作不调用模型。原先整段替换/清空记忆的命令已移除。

## Agent 工具与上下文

固定工具为 `SearchMemory`、`GetMemory`、`AddMemory`、`UpdateMemory`、`ForgetMemory`。所有工具绑定可信账号，不接受 principal、运输配置或设备凭据。`scope` 默认 `{kind:"user"}`，也可选择 `{kind:"fleet"}` 或 `{kind:"device_env",device_id:"UUID"}`，不接受跨范围移动。新增和更正的 `value` 包含 `content`、`kind`、`pinned`、`valid_until`；新增用 generation，修改/遗忘用 item_id 和 revision。变更仍经过原 PermissionMiddleware，遵守该会话已选择的权限模式，没有额外的模型审批器。

定时回合只暴露搜索与读取工具，不能借后台问候修改长期资料。普通回合仍可按用户明确要求申请变更。

系统规则前缀固定为版本化协议，动态偏好和记忆通过 canonical、仅模型可见的 `context_frame` 追加到原会话。帧含稳定消息 ID、内容哈希、隐私版本、设备目录版本、当前设备、会话/帧上下文代际、模型配置摘要和最近到期时间。内容与授权未变且完整帧仍在可见视图时复用同一 ID；变更追加完整新帧并排除旧帧，压缩、截断、clear/rewind 或模型变化后补发完整快照。初版不发引用指针，不存在指向模型看不到正文的悬空引用。

普通与定时回合使用同一个入口。首次升级遇到无帧旧历史时保守重建模型视图。工具批次结束后的下一次模型调用会刷新事实，遗忘不会再等待下一轮用户消息。模型派发前还核验快照版本和授权，遇到并发变化停止过时调用，不自动重放。压缩后的最后预算检查若移除了完整帧，模型出口补充同一授权快照；原 Agent loop 和工具审批权不变。调度器不持有记忆正文，只在执行时取当前版本。非置顶或超预算条目仍按需搜索；没有同一回合自动切换冻结执行设备。

检索使用 SQLite FTS5，应用层生成中文 Unicode 单字/双字词元与完整 ASCII 标识，结合大小写归一化的原文子串匹配。路径、符号与短编号可以原样查找，查询不作为原始 MATCH 表达式执行；排序优先完整子串，再按匹配词元数量。没有 embedding 时仍可完整使用。

默认容量：每账号 64 KiB、128 条；单条 8192 UTF-8 字节。`limits.max_memory_bytes` 可设为 256—1048576 字节。偏好独立限制 4096 字节。USER/FLEET/当前 DEVICE_ENV 置顶快照分别最多 1200/1500/2000 Unicode 字符，各自条目序列化合计最多 6000 字节；模型设备目录最多 8000 字节并报告省略数量；超出时返回 omitted，不擅自删除事实。搜索每次最多 20 条，条目合计最多 24 KiB，可继续分页。以上字节边界同时约束提示词大小，没有把字符数冒充供应商精确 token 数。

## 网页与 API

“我的设置”分别提供回复偏好和条目管理，可选择范围、搜索、添加、更正、设置有效期、置顶及确认遗忘。显示来源、范围、容量与版本。正文进入 textContent、表单 value 或 text 节点，不能作为 HTML 执行；退出或切换账号会清理正文和未完成请求的显示结果。

| 接口 | 内容 |
| --- | --- |
| `GET/POST /api/preferences` | 独立偏好及 CAS revision |
| `GET /api/memories?scope=user&query=&offset=0` | 当前账号指定范围管理视图、允许的范围目录，含过期资料 |
| `POST /api/memories` | `{request_id, generation, scope, value}` |
| `GET /api/memories/{id}?scope=user` | 当前账号条目详情 |
| `POST /api/memories/{id}/edit` | `{revision, scope, value}` |
| `POST /api/memories/{id}/forget` | `{revision, scope}` |

查询 scope 为 `user`、`fleet` 或 `device_env:UUID`，写入 scope 使用与工具相同的对象，省略时为 user。CONTEXT 请求明确拒绝，未授权设备、撤销范围的新增/修改返回 403，错误不返回正文。账号本人在私人管理入口仍可查看、搜索和忘记已撤销设备的旧资料，释放其容量；该宿主权限不会注册成模型工具参数，模型仍不能读取这些条目。网页将撤销范围标为只读并保留遗忘按钮。

所有 API 使用浏览器账号；写入沿用同源与 CSRF 检查，不能由请求指定 owner。跨账号详情等同不存在，更正/遗忘与版本冲突均不产生变更。

## 升级与验证

schema 升至 13。v12 的既有条目转为 USER，增加 scope 索引及账号隐私版本；其 UUID、revision 与来源不改写。停服、备份一致的 SQLite 快照后升级。v11 及更早生产版本的 user_data 在事务内拆成 user_preferences 和 memory_items：非空旧记忆完整导入为一条 `legacy_import`，不猜测事实拆分、原始时间或消息来源；随后删除旧表。重复启动不重复导入。

旧 `ReadMemory`/`WriteMemory`、`UserData`、`/api/user-data` 及整段替换写法已经移除。部署配置将 `max_user_data_bytes` 改为 `max_memory_bytes`；示例已更新，不提供双写或兼容别名。回退程序必须同时恢复旧版数据库备份。

```sh
./scripts/cargo-rmcp-patched.sh test --locked -p peri-cloud --lib memory
./scripts/cargo-rmcp-patched.sh test --locked -p peri-cloud --test cloud_loop --test gateway --test identity --test cloud_journal
node scripts/check-memory-ui.cjs  # jsdom 由 scripts/portal-ui 提供
```

后台自省、候选箱、Skill 晋升、独立项目授权与项目文件快照仍未交付。
